Terminal dock identity on board switch

UX Design step · task b70bcbeb · builds on the Requirements step ("Terminal dock identity on board switch") · 2026-08-27

Display-layer only New: the elsewhere marker No teardown, no new dialogs
Design thesis. Requirements established that the data already knows every session's true board — only the rendering asks the wrong question. So the fix is one rule plus one exception-marker:

Rule — identity is stamped, not inherited. Every label on every surface derives from the session's own board title (captured at launch, carried in the entry/registry row), never from the board currently on screen. Navigation can never change what a tab says (Requirements AC 1, 2, 4).

Exception marker — mark the stranger, not the crowd. While a session's board ≠ the board being viewed, that tab (and only that tab) gains a small indigo board-glyph, and its pane header promotes the board name from quiet mono text into a visible, clickable board chip. Same-board sessions look exactly as they do today — zero new chrome for the 95% case (AC 3).

Three deliberate moves: (1) the board name is promoted from 12px mono grey into an indigo chip — same badge grammar as Auto-accept (amber) and Read-only (violet), so it reads as "a fact about this session" at a glance; (2) the working folder joins the identity line — the folder is the ground truth of where a command lands, and this header is the last thing a user sees before typing into the wrong project; (3) the chip is a real link: hover/focus reveals "Open board →", one click takes you to the session's true board — the cheapest possible recovery from "wait, this is the wrong one". It's informational first, navigational second; Escape-free, dismissal-free, no dialog (Requirements AC 7).

B3 — Legacy session with no recorded board (Requirements open question c)

● Connected Board not recorded · session 77aa41b2 · ~/projects/old-side-project ⧉ Pop out🔓 Read-only⏻ End

Decision: never guess, never alarm. A registry row that predates the ideaId field gets "Board not recorded" in the quiet mono identity line with its folder as the disambiguator — the folder is always known for resumable sessions and is the actual truth anyway. It gets no indigo marker on its tab (we can't know it's elsewhere, and a false "stranger" flag would teach users to ignore the marker). The tab label falls back to "Session · 77aa" exactly as resolveSessionName already does with a blank idea title. Since the registry window is 48 hours and all new sessions are stamped, this state self-retires within two days of shipping.

Tabs are 110–190px; the marker answers "is this mine-here?" but not "which board, which folder?". Hovering or keyboard-focusing any tab shows the full identity (shadcn Tooltip, replacing today's native title string on the tab — same content, richer scent):

Inside the popped window there is no "currently viewed board", so the board chip renders always (it's the window's only board context) and its link opens the session's board in the main app. The dock-side violet "popped out" chip keeps the same stamped label.

E · Behaviour decisions

E1 — Open question (a): the pristine, never-launched tab

It follows navigation — deliberately. The pristine slot has no session; it is a launch surface, not an identity. On a board switch it re-targets the newly-viewed board (title, GitHub URL, recorded folders), shows no marker, and its idle/setup copy names the new board. This is what makes AC 8 true ("new launches still target the newly-viewed board") and it costs nothing: there is no user investment in a pristine tab to protect. The instant a launch mints a session, identity is stamped and stops following.

E2 — Open question (b): how to signal "targets another board" without cluttering the strip

Exception-only marking, glyph not words. Only cross-board tabs get the 12px indigo board-glyph (mockup A). No text chip in the strip — at 110px minimum tab width a chip would crush labels below usefulness. Indigo is a new, single-purpose hue in the dock's vocabulary (emerald = healthy, amber = attention, rose = failed, sky = active/selected, violet = popped out), so it can't be misread as a connection state; and the signal is never colour-only: the glyph is a distinct shape (a kanban board), it carries sr-only text ("On another board: Recipe Saver"), and the tooltip and pane header repeat the fact in words.

E3 — Open question (c): registry rows predating ideaId

Never guess, never alarm — mockup B3. "Board not recorded" + working folder in the identity line; no marker (no false positives); fallback label "Session · sid4" as the naming rule already produces. Ages out with the 48h registry window.

E4 — Rename, toasts, announcements

  • Rename changes the name, never the identity. The rename flow is untouched; a renamed cross-board tab keeps its marker (the name can't carry the board). The rename-failure toast names the session by its resolved label and, when cross-board, appends the board: Couldn't rename "deploy fix" (Recipe Saver).
  • Announcements get parity, not verbosity (AC 6): the existing attention announcement becomes Terminal "deploy fix" (on board Recipe Saver): reconnecting for cross-board sessions only; same-board announcements are unchanged. Split-pane, drag-ghost and collapsed-bar labels all flow from the same stamped derivation, so they inherit the fix without their own rules.
  • The drag ghost reuses the tab's exact contents (status glyph + marker + label) — what you grab is what you saw.
Explicit non-goals: no prompt, dialog or confirmation on board switch (Requirements AC 7 and the dock's own hard rule: never trap the user); no session teardown or re-parenting; no change to the chooser or My Sessions panel, which already tell the truth — they are the pattern source ("Running now — other boards"), not a change target.

F · Rationale — design lenses

LensHow this design uses it
Gestalt — Similarity / anomalySame-board tabs stay visually uniform; the single indigo glyph makes the cross-board tab the visible odd-one-out. Marking the exception exploits pre-attentive pop-out — no reading required to answer "which of these isn't from here?" (AC 3).
Gestalt — ProximityThe marker sits inside the tab, touching the label it qualifies; the board chip sits in the pane header's identity cluster, next to session id and folder — facts about one session are grouped, facts about the dock (split toggle, +) stay in the utility area.
Fitts's LawThe recovery action ("Open board →") lives on the chip the user is already reading/hovering, not in a menu across the screen. The chip's hit area is the full 24px-tall badge; the tooltip anchors to the cursor's tab.
Hick's LawZero new decisions on board switch — no prompt, no mode. The only added choice (visit the session's board) is optional and single-click. Progressive disclosure: glyph → tooltip → header chip → navigation, each level adding detail only when sought.
Information scentA board-shaped icon means "board"; the tooltip says exactly what happens if you type ("commands run in this folder"); the chip's hover text says exactly where the click goes ("Open board").
Jakob's LawMirrors VS Code's remote-window indicator and browser tab favicons: a small leading mark declaring "where this really lives", with the window/tab title carrying the same fact. The badge grammar (bordered tinted chip) is the dock's own established Auto-accept/Read-only pattern.
Recognition over recallThe user never has to remember which board a session came from — every surface states it. The fallback label embeds the board name; named sessions get the marker + tooltip instead.
WCAG 2.1 AAIndigo #a5b4fc on #141417 ≈ 8.9:1; never colour-only (distinct glyph shape + sr-only + words); tooltip opens on keyboard focus; the chip is a real link with a visible focus ring; all states have text equivalents in aria announcements.
