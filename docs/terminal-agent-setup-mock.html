Setting up Claude Code or Codex from the browser terminal

Design mock for the "in-app setup" card (stage 1), for Nick to approve before anything is built. Every panel is rebuilt from the real terminal panel's colours, sizes and controls, the same way as the approved "browser terminal on a new Mac" mock. Wording is final unless you change it. 11 Nov 2026.

What changes, in one paragraph. Today, if you start Claude Code or Codex in the browser terminal on a Mac that doesn't have it, the tab says "isn't installed on this Mac" with a link to the maker's website, and that's the end of it. With this change the same tab turns into a short setup screen: Install (one click; the VibeCodes helper runs the maker's own installer on your Mac and you watch it in the tab), then Sign in (one click; the agent's own sign-in page opens in your browser), then Start (a normal session, which connects to your board the first time, exactly as today). Nothing runs until you click. Older helpers get the "copy this command into Terminal" version instead, with an Update button. This needs a new release of the Mac helper app.

10 · Decisions for Nick

D1 · How the install happens

  1. Recommended: one click in the tab. The helper runs the maker's own installer (the exact line their website tells you to paste) and you watch it. Needs a helper release.
  2. Copy-and-paste only: we show the command, you paste it into the Mac's Terminal app. No helper release, but you leave VibeCodes, which is what the card wanted to avoid. (Kept anyway as the fallback, screen 7.)
  3. Keep today's link to the maker's page.

D2 · Sign-in as its own step, or let the agent ask when it first starts

  1. Recommended: its own step (screens 3 to 5). The tab can tell you it worked, and your first real session starts already signed in, so the start-up instructions that connect it to the board aren't held up behind sign-in screens. Not yet checked: whether those instructions survive the agent's own first-run sign-in; this design doesn't depend on it.
  2. Skip the step: after installing, go straight to Start, and the agent shows its own welcome and sign-in screens in the tab.

D3 · The steps list is a new kind of control in the terminal panel

Nothing in the terminal panel lists steps today; the closest is the single-message ended screen. I kept that screen's layout (icon, title, one line, one green main button, small grey links) and added a three-row checklist in the middle. Recommended: keep the checklist, because it tells a brand-new user how far they have to go. The alternative is one step per screen with no list.

D4 · What stage 1 covers

Recommended: only the screen you meet after a launch fails (this mock). The launch menus' greyed-out "Codex isn't installed on this Mac" items, and a "not signed in" warning before you click, move to stage 2 (another helper release). Stage 1 changes nothing in the menus.

D5 · How we test it for real

Both agents are installed and signed in on your laptop and the Mac mini, and another always-on assistant uses Claude Code on the mini, so we must not remove them there. Recommended: a spare macOS user account on the laptop (you create it and sign in to VibeCodes there once), which is a true "new Mac". The alternative is testing only with pretend installers and your word on the real run.

Kept the same on purpose

  • The terminal line underneath ("isn't installed on this Mac… Install it, then start a new session: …") is unchanged except the address, which now points to each maker's current install page (two of today's three addresses redirect elsewhere, and the app and the helper disagree about Codex's).
  • "View my other sessions", "Show what happened", "Update now" and "Start again" are the existing controls, unchanged.
  • Claude Code and Codex get the same screens, labels and button positions; the only differences are the maker's command, the account name and the code option (screen 8).
