Interaction spec

AspectBehaviour
PlacementGhost “+” icon button in the column header, immediately left of the “…” column-options button. Same 28×28 visual size and hover treatment; a pseudo-element extends the hit area to 44×44 for touch. Header title, count and menu are never obscured.
OpenClick/tap/Enter on “+” renders the composer as the first item of the task list (in normal flow — not a popover or modal), auto-focuses the textarea, and scrolls the column to top if the user had scrolled down. The “+” becomes “×”.
CreateEnter or “Add task” button. Trimmed-empty titles are rejected inline. Optimistic card inserts at position first.position − 1000 (existing gap scheme); composer clears and stays open focused for rapid multi-add. Realtime pushes the card to other viewers at the top.
CancelEsc, outside-click, the “×” in the header, or the Cancel button — all always work (never trap the user). If text was typed, outside-click keeps the composer open once and shows the hint “Press Esc again to discard”; Esc always closes immediately.
ErrorOptimistic card rolls back, toast.error() fires, composer re-opens pre-filled with the failed title, primary button reads “Retry”. No typed text is ever lost.
Mobile (375px)Identical flow — inline composer, no sheet/modal, so the on-screen keyboard never covers a floating dialog. All targets ≥44px effective. The bottom “Add task” bar remains for users who want the full editor.
Keyboard & a11y“+” is in the header tab order with aria-label “Add task to top of {column}”. Textarea has a visually-hidden <label>. Focus returns to the “+” button on close. Error message is role="alert". Contrast: all text ≥4.5:1 on zinc-900 (error red-400 = 4.6:1).
Read-only / guestButton not rendered at all (mirrors existing isReadOnly handling), never disabled-without-explanation.
