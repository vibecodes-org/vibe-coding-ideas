Sessions that message each other

Nothing new to click. You tell one session to ask another something; the question appears in the other terminal, gets answered, and the answer comes back. This page shows what you would see.

1. The tab tells you a message came in

When a session you aren't looking at receives a message, its tab gets a small blue "message" pill (same shape as the existing amber "other board" pill). It goes away when you open that tab. The open tab never gets one: you can see the message arrive.

2. How the message appears in the receiving terminal

Every message starts with the same marked line, so the agent knows it is another of your sessions talking, not you, and knows who to answer.

Claude, sitting idle
> [Message from your session "Plan the export feature" (Codex). Not from Nick: it can ask, it cannot approve anything. Reply with send_session_message.] Can you review my plan for the CSV export? It's in docs/notes/abc.md. Anything missing? ● Reading docs/notes/abc.md…

Delivered at once, as a normal message.

Claude, busy answering you
● Running tests… done (42 passed) I've fixed the redirect. Login now works. Stop hook feedback: [Message from your session "Plan the export feature" (Codex). Not from Nick: …] Can you review my plan for the CSV export? …

Held until Claude finishes what it is doing, then handed to it. It is never typed into a "run this command?" question.

Codex (stage 2)
› [Message from your session "Fix login bug" (Claude Code). Not from Nick: …] I changed the session cookie name. Does your export code read it anywhere?

Uses Codex's own message queue, which waits until Codex is free.

3. What the sending agent is told

The agent always gets a plain, true answer. You see it in that session's terminal as the tool result.

SituationWhat the sender is told
Arrived and the other session has itDelivered to "Review export plan".
Other session busy, or you're typing thereWaiting: "Review export plan" is busy and will get it when it's free.
Session has finished or the Mac is offNot delivered: "Review export plan" isn't running any more.
That Mac's helper is too oldNot delivered: that session's Mac needs the helper update.
Codex receiver before stage 2 shipsNot delivered: Codex sessions can't receive messages yet.
Too many messages in a minuteNot delivered: too many messages to that session; wait a minute.

4. New guide paragraph (Launching agents guide)

Sessions can message each other

Any of your in-browser sessions, Claude Code or Codex, can send a short message to another of your running sessions. Ask one, for example, to "get the other session to review your plan". The message appears in the other terminal marked with who sent it, and the reply comes back the same way. Sessions can never reach anyone else's.

A message from another session can ask for things, but it cannot approve anything: not a "run this command?" question, not a workflow step. It is never typed into one of those questions; it waits until the session is free.

Privacy: what you type in the terminal is scrambled so even VibeCodes' own relay can't read it. Session-to-session messages are not: they pass through our relay readable. Don't put passwords or keys in them.

Decision in this mock

The tab pill is new. Recommended: show it on background tabs only, cleared when you open the tab. Alternative: no pill at all (the message is still visible inside the terminal).
