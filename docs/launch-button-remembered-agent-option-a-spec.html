CopyYour launch button now starts {AGENT_LABEL[agent]}. Change it any time from the button's menu. — the agent name is bold in the mock (pass a ReactNode message to sonner, or plain text if the toast component can't render markup; bold is a nicety, the words are the contract).

TriggerOnly a picker write (browser chooser "Run it with", or per-task "Start fresh with") that changes the stored value, while the account's seen-flag is unset. Footer "Switch to …" never triggers it. Same-value writes never trigger it. Picker writes never block or delay a launch.
Once per accountThe seen-flag is stored against the account (Requirements: new column users.terminal_agent_toast_seen_at, migration 00176), so a new browser or Mac does not show it again. It is set as soon as the toast is shown, regardless of whether Undo is clicked.
Where / whenStandard sonner position (as every other toast in the app). Use the regular toast() (not error/success). Suggest a slightly longer duration than the default (e.g. 8 s) because it carries an action — a behaviour tweak, not a visual one.
Accessibilityrole="status" as the mock shows; sonner supplies this. Undo is a real button, keyboard-focusable.

5. The 5-point precedence rule (binding, verbatim from the approved mock)

  1. The green button launches the agent named in its label, in a terminal window. Its label is always the account's remembered agent. Nothing else influences it.
  2. Every dropdown item launches exactly what it says, regardless of the remembered agent, and never changes the remembered agent.
  3. Only two things write the remembered agent: any "Run it with / Start fresh with" picker (as today), and the menu footer "Switch to …" link (new). Both are explicit user acts.
  4. The first time the label changes because of a picker toggle (not the footer link), show the toast once, with Undo, then never again.
  5. A primary Codex click runs the same pre-flight as the dropdown's "Codex › In a terminal window" today, and when a folder is missing it opens the folder dialog and continues the launch after save.

9. Guard-rails the builder must not cross

  • Nothing is added to any launch link; no new URL parameter; the compact prompt's protected head gains no words. deep-link.test.ts and the guide-bootstrap budget test stay exactly as they are; the folder is never dropped to fit (cwdPolicy: "keep" on the browser launch).
  • Agent names only via AGENT_LABEL — never colour alone, never a hand-typed "Claude Code".
  • The remembered agent lives in users.terminal_agent, read through the existing hook — no second store, no browser-only copy.
  • Never trap the user: the folder dialog opened by a Codex primary click closes via its button, Escape and outside-click.
  • Terminal-window vs browser stays a distinct choice in the menu — do not collapse the four agent items into two.
  • The split button stays desktop-only (hidden md:inline-flex); phones get the copy improvement in §4, never a launch.
  • Nothing visible in the approved mock is changed without going back to Nick — the four wording conflicts in §6 are flagged for the Design Review gate, not decided unilaterally here.
