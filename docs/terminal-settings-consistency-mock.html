Claude and Codex terminal settings, laid out the same way

Both agents get the same three settings, in the same order, with the same names, the same "go back to the site's choice" button and the same shape of help line, on your Settings screen and on the Admin page. Nothing about how sessions start changes. The controls are clickable so you can try the help lines.

1. Settings → Model Tiers → Terminal sessions

One small heading per agent, then the same three rows under each: Starting model, Starting effort, Memory limit. Every row starts with a "Default" choice that names the site's setting. Codex keeps its model and effort together, so on Codex picking "Default" on either row puts both back to the site's pair, and the effort buttons grey out while the model is on Default. The dialog keeps its single Save.

2. Admin → Platform: one card per agent instead of five cards

The five cards (Codex model and effort, Claude model, Claude effort, Claude memory limit, Codex memory limit) become two: Claude Code terminal sessions and Codex terminal sessions, with the same three rows as Settings. Each choice starts with "Not set", which replaces the red Clear button. Each row says who last changed it. One Save per card saves only the rows you changed, each in its own place, so changing one never wipes another.

4. Your decisions

  1. Admin: two cards, one per agent, instead of five. Each holds model, effort and memory limit with one Save. Behind the scenes every setting is still saved on its own. Recommended. The other way: keep five cards and only fix names and widths; it fixes the wording but not the "one feature" feel.
  2. Admin: "Not set" as the first choice replaces the red Clear button. It matches the "Default" first choice users see, and a card-wide Clear would wipe three settings at once. Recommended.
  3. Codex gets a "Default" button on its effort row. Codex saves model and effort together, so Default puts both back to the site's pair, and the effort buttons grey out (showing the site's level) while the model is on Default. Recommended. The other way, letting Codex effort follow the site on its own while you pick the model, changes how Codex settings are saved and is a bigger job.
  4. One word for the site's setting: "site". Today the screens say "Platform default", "organization default" and "site". The Admin tab keeps its name, Platform. Recommended.
  5. Claude first, then Codex, on both screens. Admin shows Codex first today. Recommended.
  6. Differences kept, because the agents really differ:
    • Codex has three memory-limit sizes and Claude five, so the Codex buttons are wider.
    • Claude's effort also applies when you resume a session; Codex's doesn't (unchanged). The help lines say so.
    • Only Claude's lines mention typing /effort and /autocompact; Codex has no such commands.
    • Claude's model list on Settings has "Custom…" (type any name); Codex's doesn't, although Admin's does. Recommended: leave it, as today.
    • Admin asks you to tick "I've checked this works" for an unknown Claude model name, but not for Codex. Recommended: leave it, as today.
  7. Help guide: fix the old "Profile → Model Tiers" wording, and add a short "Starting model and effort" paragraph next to the existing "Memory limit" one. Recommended.
