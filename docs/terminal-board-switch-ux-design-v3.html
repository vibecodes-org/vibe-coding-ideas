The terminal tab should tell the truth

Right now, if you have a terminal open and you click over to look at a different board, the terminal's tab changes its name to the new board — even though it's still really working in the old board's project. The fix: the tab always shows the project it's actually connected to, plus one small marker when that's not the board you're currently looking at.

Four pictures, one story. About a 2-minute read.

✓  Same moment, fixed: the tab still says "Board A", and the small amber marker means "this terminal belongs to a different board than the one you're looking at."

This is the proposal. The tab always shows the project it's really connected to — it never renames itself just because you moved to another board. The little amber "other board" marker is the only new thing on screen: one glance tells you "careful — this one isn't for the board I'm looking at." When you go back to Board A, the marker simply disappears and the tab looks exactly like it does today.

The same honesty in the strip above the terminal

Just above the terminal text there's a thin strip that shows what it's connected to. It gets the same treatment: it always names the real board and folder, in plain text — no marker of its own, because the amber marker already sits on the tab right above it.

One plain sentence to read it by: "You're looking at Board B, but this terminal is Board A's" — the amber marker on the tab says it once, and the strip below simply confirms the real board and folder in plain words, so the two never repeat each other.

What this does NOT change

Nothing gets closed, paused or interrupted — the terminal keeps running exactly as before, and switching boards works exactly as before. When a terminal belongs to the board you're looking at (the normal, everyday case), nothing looks any different than it does today. This is purely about the label being honest.
