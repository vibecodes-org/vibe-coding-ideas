Browser terminal on a new Mac: the new and changed screens

For card 6b2cb8ac (Nick to approve before the fix is built). Every panel below is rebuilt from the real terminal panel's colours, sizes and controls. Example projects: the public VibeCodes repo, plus made-up names (you/example-app, my-new-idea). Tags: new changed unchanged look, new timing

What changes, in one paragraph. When you start a browser terminal on a Mac, the VibeCodes helper on that Mac now works out the project folder itself before Claude Code (or Codex) starts. It uses this Mac's saved folder if it's really there; otherwise it looks for your copy of the board's GitHub project on this Mac; otherwise it downloads it into ~/projects; for a board with no GitHub project it makes a new folder. It saves the result for this Mac only. You see each step as a line in the terminal. If anything stops it, the panel says exactly why, with one Start again button, instead of "Connected" plus 90 seconds of "reconnecting".

Today "Update now" / "Download the helper" closes whichever Mac's helper happens to be connected, and ends your running sessions on every Mac. After the fix it only touches this Mac. On a Mac that has never run the helper, the download starts straight away (no "Closing the helper…" step).

Your 1 running session on this Mac will end first — Claude stops on your machine, and your files stay where they are. You can start fresh sessions as soon as the update finishes.

5 · Decisions for Nick

  1. Where the helper looks for your existing copy. Recommended: the usual code folders in your home folder (projects, code, dev, src, Developer, repos, git, GitHub, and the top of the home folder itself), two levels deep, for at most about 2 seconds. Not Documents, Desktop or Downloads: macOS would show a "VibeCodes wants to access your Documents folder" permission box. Alternative: also look in Documents (GitHub Desktop keeps projects there), accepting that one-time permission box.
  2. Folders your other Macs have saved. Recommended: ignore them completely. Each Mac uses only its own saved folder (one Mac with two network names counts as one). The search above already covers the usual places. Alternative: check another Mac's folder on this Mac as one more place to look (only used if it really is the project here).
  3. More than one copy found. Recommended: use the one you used most recently, and say where the other is (1b).
  4. Where a download goes. Recommended: ~/projects/<project name> (today's convention). If that name is taken by a different project, ~/projects/<project name>-2.
  5. Git not installed. Recommended: the helper opens Apple's installer for you (3c). Alternative: only show the message.
  6. When the folder can't be got ready. Recommended: stop and say why, with Start again (section 3). Nothing ever starts in your home folder or at the top of the disk. Alternative: start the agent in a plain folder and let it sort things out (your 17 Oct decision ruled this out; listed only for completeness).
  7. The button name. Recommended: "Start again" (your word) on these new screens, and rename today's "Launch again" button on the ended screen to match, so there's one name for one action. Alternative: say "Launch again" everywhere, as today.
  8. A second session on the same board. Today, if any session on this board is running on any Mac, a new one gets its own separate working copy (a side branch). Recommended: only do that when the other session is on the same Mac, so work on the Mac mini doesn't land on a side branch just because the MacBook is busy.
  9. Wording change in the update confirmation (4d): add "on this Mac". Recommended: yes.

6 · Where this deliberately differs from today's controls

Checked against the existing ended / error / timeout panels in the same terminal panel (CLAUDE.md "Mocks and new controls"). Each difference is kept on purpose and needs your OK:

  1. "How to install Claude Code / Codex" link (2b, 2c). No ended screen has a link like this today; the helper's terminal line already carries the address. Styled like the setup screen's "Download the x64 version" link.
  2. "Show what happened" link (2d, section 3). New. Same small underlined style as the existing "View my other sessions" link, next to it. Clicking it swaps the message for the one-line bar in 3e (grey, in the reconnecting bar's place, with a small green Start again), which is also new.
  3. Button label "Start again" instead of today's "Launch again" (decision 7). Same green button and terminal icon.
  4. Titles that name the cause ("Couldn't download example-app"). Same grey styling and square icon as today's ended titles, not the red "Error" styling, matching the calm tone of the existing setup and ended copy.
  5. Old-helper screen (2e) puts the existing blue "Update now" button first and makes Start again the outline button, because updating is the fix there. Same pairing as today's "Resume this conversation" + "Start fresh".
  6. Progress lines carry a teal "VibeCodes" tag. The helper's existing notes are yellow because they're warnings; these are information. Failure lines stay yellow like today.
  7. No new header pill while the folder is being got ready: the header keeps saying "Connected" (the link is up) and the lines explain the wait. A "Setting up…" pill was considered and left out to keep the header as it is.
