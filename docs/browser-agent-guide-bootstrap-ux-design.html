From launch to work

  1. Choose the agent and start a fresh session. Task controls preserve the selected task ID. Board controls and the dock’s fresh-session choice preserve board context. A chooser resume or reconnect continues the previous conversation and receives no new guide bootstrap.
  2. Resolve the project folder. Preserve the selected absolute folder in the browser launch link. Where an existing project is unknown or a new project must be created/cloned, complete the existing safe-directory flow first. Never inspect or write a guide in / or a home directory while searching for the project.
  3. Confirm the current checkout. Run pwd; verify it identifies the intended working checkout. Complete any required clone before inspecting guides. When isolation has already placed the session in a worktree, inspect that worktree’s root. Do not change into the main checkout to find a guide absent from this checkout.
  4. Inspect and load the guide. Apply the matrix below to the two exact root filenames. Read the applicable guide completely before normal work; create only the missing native guide, using the fallback as its source. Follow valid project guidance within the active instruction hierarchy.
  5. Finish MCP setup and record the project path. Retain each agent’s existing MCP connection/authentication and workflow-attribution directions. Once connected, record the verified main-checkout path and real hostname before task pickup. Guide inspection needs no MCP; it may precede connection. A worktree’s guide path and the recorded main-project path serve different purposes.
  6. Continue the existing work instruction. Task launch retrieves its specific task; board launch reads the current board and follows eligibility/approval safeguards. Respect the native guide’s applicable workflow requirements. Never fabricate a board assignment from the bootstrap.
Ordering constraint: safe current checkout → guide inspection/read/conditional creation → task work. MCP connection may occur before inspection, but path recording requires connection and a verified main checkout. Preserve existing setup ordering wherever it already satisfies these constraints.

Full semantic specification

After confirming the safe current project checkout, and before task work, inspect its root for {native} (your native guide) and {fallback}. If {native} exists, read and follow it; change neither guide. If only {fallback} exists, read it fully and create {native} from it, preserving substantive project guidance and adapting only agent-specific CLI/workflow directions. Create only if the destination is still absent: use a no-clobber creation operation so a concurrently created file cannot be overwritten. Then read and follow {native}; if another session created it first, use that file unchanged. Do not merge or synchronise existing guides. If neither exists, create neither and continue. If inspection, reading, or creation fails, explain the problem in the terminal and pause before task work. In a worktree, inspect and write guides only in the current checkout; keep main-checkout path recording unchanged.

Compact guide block · Codex

In the safe current checkout root, before work: read/follow AGENTS.md if present; else if CLAUDE.md exists, read it and create AGENTS.md without clobbering, preserving project guidance and adapting only agent-specific CLI/workflow directions; then read/follow AGENTS.md. Never overwrite/merge/sync existing guides, including races. Neither exists: create neither. Read/create errors: explain and pause.

“Without clobbering” requires exclusive/no-overwrite creation, not a check followed by an ordinary write. A destination-created race means read the winner’s guide unchanged, not an error requiring replacement. The compact block’s read/create error clause applies to actual failures, including inspection errors; it must not classify a concurrent successful creation as permission to overwrite.

What “adapt agent-specific directions” permits

Preserve repository architecture, commands for the project, testing, branch/release policy, database rules, security requirements, workflow gates, and substantive explanations. Adapt only directions addressed to the launched coding agent: its CLI name, MCP connection flow, tool conventions, and workflow attribution.

Example: a Codex guide uses the existing Codex MCP setup and agent: "codex" workflow attribution from the launch bootstrap, rather than instructing Codex to execute Claude’s /mcp flow. Claude receives its corresponding existing connector flow. Do not apply a global name replacement to documentation that legitimately describes both products. Preserve links, code examples, and non-agent project behavior.

If an agent-specific instruction has no clear equivalent, preserve the underlying project requirement, identify the unresolved mapping in terminal narration, and pause if it blocks safe work. Do not invent CLI syntax, erase an approval gate, or rewrite the source guide.

The policy must survive the URL budget

The existing prompt is already close to its limit. Adding the guide clause to a trimmable tail would make behavior depend on path length, board title, and agent choice. Protect the complete guide rule as required bootstrap content on all fresh browser paths.

  1. Retain the required launch information. Preserve the folder parameter, selected agent, safe-directory/worktree policy, MCP connection and attribution, main-path recording, guide policy, and a minimal task/board work instruction carrying the relevant IDs.
  2. Reduce optional copy atomically. Shorten titles/descriptions and optional duplicate directory narration using the existing degradation approach. Compact equivalent wording is allowed; deleting required semantics or cutting a clause mid-sentence is not.
  3. Measure the final encoded link. Account for actual session/token overhead, folder, selected agent/model/effort, isolation flags, and query encoding. Keep existing limits. A realistic launch must still succeed; newly rejecting normal cases is a regression to resolve during implementation.
  4. Refuse an impossible launch visibly. If the complete required policy plus retained folder cannot fit, do not fire a link or start a session with partial instructions. If the existing flow has already minted a pending session, use its existing failure cleanup. Preserve the user’s chosen agent and folder for recovery.
Launch refusal copy: “This browser launch is too long to include the required setup instructions. Use Copy command from the launch menu, or choose a shorter project folder path.”

This copy is appropriate only if the offered copy-command path includes the same complete guide policy for the selected agent. Otherwise use: “This browser launch is too long to include the required setup instructions. Choose a shorter project folder path and try again.” Reuse the existing launch error/toast surface; keep the full error readable in the launch panel if that surface is persistent. Never silently drop the folder or suggest changing the board/task identity.

Implementation may improve packing of the protected content to fit realistic URLs, with semantic equivalence tests. Do not raise the URL cap or introduce a server/helper filesystem protocol as a shortcut. Desktop launch redesign, resume bootstrapping, and helper releases are outside this design.
