## Fix step (Atlas, 14 Oct) - what was built and why
- Cap: `ENHANCE_MAX_OUTPUT_TOKENS = 32000` in new `src/lib/enhance-stream.ts` (no effort option, per Nick). enhance-create keeps 4,000.
- Deadline: `createDeadlineSignal` (270 s from request start) passed as `abortSignal`. The reader loop races each read against the abort, so a stream that ignores the abort still ends. On deadline: marker + close; usage logging is raced against a 5 s wait so it can never hang the response.
- Continue: route `continueFrom` mode (original + answers + text so far + "ONLY the remaining part"), separate from refine; same helper used by enhance-create. Dialog appends to the existing text and re-sends the first run answers.
- Dropped connection: if some text arrived, stay on the result screen with the amber bar (own wording) + Continue; toast kept. Nothing arrived: back to the first screen. If a Continue request fails before the stream starts, the earlier result is restored as it was (small addition, same spirit).
- Discard confirm: existing AlertDialog component; "Keep result" / "Discard". Escape/outside click on the confirm keeps the result. Also asks in the refine screen (a result is on screen there too). Footer Cancel goes through the same check; Apply is not affected.
- Deviations from the plan: no effort setting (Nick); deadline logic lives in the shared helper file rather than ai-helpers (route tests mock ai-helpers). Guide pages: no wording about enhance truncation or limits, nothing to change.
- Test 5 (dropped connection) uses a pull-based stream because a stream error() discards queued chunks.
