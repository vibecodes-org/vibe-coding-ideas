## Decided (proposed, awaiting Nick)
- Stage 1 (VibeCodes): the helper's bridge totals its conversation's main-window usage that steps did not already
  take, by hour, and sends it to a new bridge route; get_cost_report adds per-board weekly main-window series, a
  total series and a short "sessions this week" list. User-facing change: NO (tool reply only).
- Rule: per main call, attributed = (finished claims open at that call) / (all claims open at that call, incl.
  never-finished); own = 1 - attributed. So own + step share = every main call, nothing counted twice or dropped.
  Claim opens at the claim_next_step result, closes at the first of: a Bash call holding its vcu_ marker, or the
  accepted complete/fail result carrying its ct_ token (same as the live command).
- Board comes from the session row on the server, never from the request. Conversation id must match the row's.
- Stage 2 (other repo, needs the assistant's approval): Saturday review shows main window vs steps per board,
  and the top sessions. Mock at that stage.

## Ruled out
- Riding on each finished step's usage command: no helper release, but misses everything after a session's last
  step and every chat-only session; that tail is exactly what 72debfc0 changes, so the comparison would be biased.
- Doing it only in the Saturday review: it maps by project folder, and the bot's own folder hosts both its always-on
  session and a board's coordinator; it can't see which conversation belongs to which board.
- Day buckets: report weeks end at the allowance reset (Sat 06:00 UTC), so hourly buckets.
- Codex sessions: no comparable records; not counted (said in the tool text).
