# Card 92ead215 - drag highlight can differ from where the card lands

User-visible effect: only removes a wrong highlight in a rare layout-shift case. No stored data, auth or payments.

## Root cause
In `handleDragOver` (src/components/board/kanban-board.tsx) the column highlight (`setDragOverColumnId`) was set to the
column the collision check reported BEFORE the echo guard from card 2bc396fd (`isLayoutEchoHop`) decided to ignore the
hop. After an ignored hop the highlight showed the reported column while the card stayed in, and dropped into, the other.
Dragging code reproduces: hop todo->backlog, then an event reporting todo with identical pointer delta: highlight=todo,
card in backlog. Introduced by PR 396 (25 Oct).

## Fix
New pure `resolveDragOver` in drag-column-hop.ts returns the column the card lands in plus the hop to record; the
board highlights that column. Same hop rules as before, so the loop guard is unchanged (it only moved the highlight call).
Test: drag-column-hop.test.ts "resolveDragOver" (failed before, passes after).
