# Card fe1896ee: warn on the board when a run has many steps with no cost recorded

Background: card 730f2549 (see docs/notes/730f2549.md). Plan written 12 Nov 2026.

## What the live data says (read-only queries, 12 Nov 2026)

- `workflow_step_unmeasured` (one row per finished attempt with no cost, migration 00204) has rows from 26 Oct onward:
  214 (week of 26 Oct), 118 (2 Nov), 12 (9 Nov, to date). All kind `unavailable`. No `codex` rows yet.
- 303 of them carry the reason "Session sandbox refuses to run the usage script from this isolated worktree"
  (30 Oct to 3 Nov): the problem card 730f2549 fixed.
- The rest (about 40) are deliberate: "no helper ran" / review skipped / step claimed only to send back. These
  come 1 per run (36 runs) or 2 per run (2 runs), never more.
- Every run hit by the refusal that had 3+ records was refusal-only (21 runs, 3 to 47 records each). Runs in a
  looping workflow redo the same 4 steps many times, so counting distinct steps would cap at 4 and hide the
  scale; count finished attempts (rows) instead.
- Finished agent steps with neither a cost row nor a reason: 21 (week of 12 Oct), 3, then 0, 0, 2. Since sessions
  must now send one or the other, "nothing reported at all" is rare; the reason table is the signal.
- The weekly cost report's "cost missing" counts a step only when it has no cost at all, so a looping run with
  some costed attempts doesn't show there. That's why this warning counts attempts.
- `workflow_step_unmeasured` is NOT in the realtime publication (task_workflow_steps and workflow_runs are).
  The row is written just after the step's status update (mcp-server/src/tools/workflows.ts ~1794 ->
  recordStepUsage -> recordUnmeasured), so a card refetch triggered by the status change can miss it.
- workflow_runs columns: id, task_id, template_id, status, current_step, started_by, started_at, completed_at,
  created_at (no idea_id).

## Decisions (proposed, waiting on Nick)

1. Threshold: 3 or more finished attempts with no cost in one run (Codex records excluded). Fits the data:
   catches all bad runs, no deliberate ones.
2. Board strip window: last 7 days (by the record's created_at).
3. Places: amber strip at the top of the board (same component shape as the setup strip) plus an amber note in
   the card's Workflow section (same look as the "no matching agent" note). Live run only in the card.
4. Dismiss: same as the setup strip: sessionStorage, comes back when the number of flagged cards goes up.
5. Notification ping: not in stage 1; stage 2 if Nick wants it.
6. Team members only (hidden for read-only viewers), like the setup strip.

Ruled out: counting distinct steps (hides looping runs); a weekly total per board (deliberate skips across many
runs would trip it); a new column on board_tasks or a database view (not needed: two small reads); realtime for the
new table (would need a migration; stage 1 refreshes on page load and on the card's next update).

## Build (12 Nov 2026): approved changes and decisions

Nick approval overrides the proposals above: threshold is ONE record per run; board strip looks back 14 days; both strip and card note; no notification; team members only.

- "Deliberately skipped with a written reason" has no column (those rows are kind unavailable with a reason, same as the worktree refusal). So isDeliberateSkip in src/lib/step-cost/unmeasured-alert.ts reads the reason text: starts with "No helper/subagent" or contains "review skipped". All 40 deliberate reasons in live data (12 Nov) match; the refusal text does not. Weak spot: a differently worded skip raises the warning; a real failure worded "No helper..." is hidden.
- Strip title says "in the last 14 days" (mock said "this week"). With no quotable reason the strip says "Most often: <label>".
- Kept counting finished attempts, not distinct steps.
- Reads: src/lib/step-cost/unmeasured-alert-loader.ts (board page, paged, errors logged, no strip on failure); card note reads in task-workflow-section.tsx (failed read = no note, logged).
- No database change. One guide sentence added in src/app/guide/workflows/page.tsx.
