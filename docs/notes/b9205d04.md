## Decisions (pending Nick's approval)
1. **The MCP reply delivers the file.** `sync_board_agents` takes `step_id`, builds that one step's agent, and returns a ready-made shell command with the file inside it (a quoted heredoc). It also returns a fingerprint, so no network is needed. The command picks the folder, writes to a temp file, and checks the sha256. On a mismatch it deletes the temp file, so an unverified persona never lands. Otherwise it moves the file into place, sets up git ignore and pauses 5s. Its last line is READY, NEW_FOLDER or MISMATCH.
   - The command goes in its own raw text block, not inside JSON, so the model copies real newlines rather than `\n` escapes.
   - Fingerprint: sha256 after removing trailing whitespace on every line (ASCII only, `LC_ALL=C`) and trailing newlines at the end. That tolerates whitespace slips in retyping but catches any real edit.
   - Hash tool: `sha256sum` or `shasum -a 256` (stock macOS has no `sha256sum`).
   - Ruled out: Write tool plus a separate verify command. That's three calls, and the folder check has to happen before Write creates the folder. Also ruled out: text the model assembles itself, which reopens the editing risk.
2. **Remove the download path** (`/api/terminal/agent-files`, `agent-files-token.ts`, the tar builder, `syncCommand`). Recommended: with one path that works on every network, the claim text stays short, and the URL token (Lens note 6) goes away. Kept: `renderAgentFile` / `parseAgentFile`, and the loader the bridge uses.
3. **No one-turn delay:** run the command with `run_in_background`, end the turn, and the completion wakes the session (proven unattended and in `-p`). The 5s pause covers the watcher race. Safety net: if the agent still isn't offered after READY, run one more background `sleep 5` and end the turn again; after that, use the general path.
   - Can't background (a subagent orchestrator, or `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`): run it in the foreground and use the general path for this step. The file is ready for the next claim.
4. **New repos.** A folder created mid-session never loads; that's proven, and no code can change it. The plan gets as close as possible:
   - (a) The command writes to `.claude/agents/` if it exists, otherwise to the user folder (`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/agents`) if that exists.
   - (b) If neither exists, it creates `.claude/agents/` plus `.gitignore` (`vc-*.md`) and reports NEW_FOLDER. The session uses the general path for this step, doesn't sync again this session, includes the `.gitignore` in its next commit, and tells the user.
   - (c) The guide gives the one-time fix that removes even that first session: `mkdir -p ~/.claude/agents` once on the Mac, or as a line in the cloud environment's setup script.
5. **Stale copies (Lens note 2):** files written by the sync get a description that starts "Saved by sync_board_agents." When a claim's agent is offered with a different tag:
   - with that marker, re-sync;
   - without it, VibeCodes launched the session with `--agents`, which beats files on a name clash, so skip the sync and use the general path.
   Also: never sync again after a failure in the same session.
6. **Stdio works now:** no signing secret is needed, so the local stdio server can serve the sync too. That removes the stdio refusal (Lens note 2).
7. `step_id`, not an agent name. The server builds exactly the claimed step's agent and resolves the tier the way `claim_next_step` does. A name prefix can't identify a bot safely.
8. Codex: out of scope (card e16d69e8).
