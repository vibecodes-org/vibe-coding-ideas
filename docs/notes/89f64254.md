# 89f64254: Claude Code session started with Codex's instructions

Quick-fix notes (Atlas, 14 Nov 2026).

## What happened
A new in-app terminal session on a board started Claude Code, but the opening
instructions were the Codex ones: `codex mcp add vibecodes`, "do NOT use claude
mcp add or /mcp", "pass agent: codex", and the AGENTS.md guide step. Claude
noticed and asked which agent to report as.

## What I checked
- The screenshot on the card: a board-level launch (the "find work, but ask
  first" step, no card), header pill "Claude Code", Codex wording in steps 1-2.
- The session's row in `terminal_sessions` (read-only): `agent = claude`, no
  task. So the session was requested as Claude; only the instructions were
  Codex's.
- Every builder of the instructions (`buildCompactPromptEssentials` callers:
  launch button, card launch payload, the terminal hook's own fallback) words
  them for the same agent it puts on the launch. None of them mixes agents.
- The dock is the one place the agent is changed after the instructions are
  built. A launch from the button waits in the dock as `pendingLaunch` with its
  instructions already written. "Start new session" (session chooser) and
  "Start fresh anyway" (card dialog) then did
  `{ ...pendingLaunch, agent: <picker value> }`: new agent, old instructions.
  The hook passes a launch that already has instructions through untouched, so
  the mismatch reached the session.

## Cause
Switching the agent picker in the dock after a launch was built for the other
agent changed which agent starts, but not the instructions it is given. It
works both ways: Codex could equally be started with Claude's instructions.

## Fix
- `buildCompactPromptEssentials` now remembers what each result was built
  from, and `essentialsForAgent` rebuilds the same launch for the other agent
  from that. Same folder, same board, same card; only the agent changes.
- The record is kept beside the object (a WeakMap), not as a new field on it.
  A field was tried first and broke four existing tests that pin the
  instructions as exactly identical across different inputs.
- `withLaunchAgent` (`src/lib/terminal/task-launch-payload.ts`) is the one
  place the dock applies the picker's agent to a waiting launch. Both dock
  handlers use it.
- No wording changed, so the launch-link length budget is untouched.

## Decisions
- Rebuild rather than drop the instructions and let the hook rebuild: the
  hook's fallback is board-level only, so a card launch would have lost its
  card.
- Instructions that can't be rebuilt (a hand-made or copied object; no real
  launch does this today) are removed when the agent changes, with a warning
  in the log. The terminal then writes the board's standard instructions for
  the agent that starts. Wrong-agent instructions are never sent.
- A launch switched to Codex now gets the Codex guide step and its
  all-or-nothing fit rule, exactly as a launch started as Codex does.

## Not changed
- The "Ready when you are" panel's picker is ignored when a built launch is
  already waiting on that tab (the agent and instructions stay those of the
  waiting launch, so they agree). Left alone: not this bug.
