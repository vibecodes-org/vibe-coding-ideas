# 279b94ae: daily check for a newer Sonnet

Working notes for the Plan step (10 Nov 2026). Later steps read this.

## What the card wants
A daily job that spots a new Sonnet, test-drives it with the app's three real AI
request shapes on the platform key, and puts one "switch?" (or "fails") card on
this board. It never switches the model itself.

## Facts checked (against origin/master 8b058d3 and live data, 10 Nov)
- `AI_MODEL` in `src/lib/ai-helpers.ts` = `ANTHROPIC_MODEL?.trim() || "claude-sonnet-5-5"`.
  Vercel has `ANTHROPIC_MODEL` set for production only. `ai_usage_log` shows
  production on `claude-sonnet-5-5` since 10 Oct (card c042df6e).
- The three option sets exist as the card says:
  `ANTHROPIC_STRUCTURED_OUTPUT_OPTIONS`, `ANTHROPIC_STRUCTURED_OUTPUT_LOW_EFFORT_OPTIONS`,
  `ANTHROPIC_LOW_EFFORT_OPTIONS`.
- **Card is stale on one number:** task generation's cap is now 32,000
  (`GENERATE_TASKS_MAX_OUTPUT_TOKENS` in `src/lib/generate-tasks-stream.ts`), not 8,000.
  Matching = `generateObject`, low-effort structured, cap 500 (`src/lib/workflow-matching.ts`).
  Short rewrite = `enhanceTaskDescription` in `src/actions/ai.ts`, `generateText`, low effort, cap 1000.
- **No Vercel cron exists yet.** `vercel.json` only has `ignoreCommand`. No `CRON_SECRET`
  anywhere in the code and none in the Vercel project's env vars. Existing scheduled things
  are pg_cron (database-only jobs) and one GitHub Actions probe. So this card adds the
  first Vercel cron and Nick must create `CRON_SECRET` in Vercel.
- The schemas the test should reuse are private today: `GeneratedBoardSchema`
  (route-local in `src/app/api/ai/generate-tasks/route.ts`, duplicated in `ai.ts` and
  `onboarding.ts`) and `adjudicationSchema` (`src/lib/workflow-matching.ts`).
- `platform_settings` (key text PK, value jsonb, updated_by, updated_at) is the right
  home for "last seen": rows today are model_tier_defaults and four terminal_* keys.
  Service role bypasses its super-admin write policy. No migration needed.
- `ai_usage_log.action_type` has a CHECK list; logging the test-drive there would
  need a migration. Decided not to (see below).
- Auto-workflow rules are applied in app code (`checkAndApplyAutoRules`), not by a DB
  trigger, so a plain service-role insert into `board_tasks` gets no workflow.
- Board columns (this idea): To Do = position 1000, found by title at run time.
- Middleware: no `/api` path is login-protected; `api/notifications/email` already works
  with header auth. Excluding `api/cron` from the matcher is hygiene only.

## Decisions (recommended, awaiting Nick)
1. Test-drive usage is NOT written to `ai_usage_log` (needs a migration and would sit
   in the user cost reports); the card shows token counts instead.
2. The new card has no labels, so no workflow attaches: it is a decision for Nick.
3. Retry once on overloaded / rate-limit / 5xx before calling a check failed.
4. First run with nothing recorded and newest == current: record silently, no card.
5. Re-testing a model that failed is out of scope (manual for now).

## Ruled out
- Auto-switching (card's own reasoning: Sonnet 5.5 forced-tool-choice break, the Haiku
  key-access failure).
- pg_cron + pg_net calling the route: adds the secret to the database; Vercel cron is simpler.
- GitHub Actions schedule: would need the secret in GitHub too; Vercel cron sends it itself.
- A model id + date string compare for "newer": Models API `created_at` is the source.
