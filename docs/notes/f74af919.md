  all workflows (Node 20 is past end of life; worth its own card, not this one).
- Pinning every workflow to 24.04: the others work on 26.04; pinning them just delays the move.
- Pinning only, forever: GitHub will retire 24.04 eventually (no date announced that I found).

### What I checked (10 Nov)
- `@playwright/test` 1.64.1: requires Node >=20, depends on `playwright` 1.64.1 exactly, which
  depends on `playwright-core` 1.64.1 (npm view). Published 14 Oct; 1.65.0 on 5 Nov.
- Lockfile: only one Playwright chain (`@playwright/test` -> `playwright` -> `playwright-core`,
  all 1.58.2). Nothing else in the repo depends on Playwright; mcp-server and terminal don't use it.
- Only `.github/workflows/e2e.yml` installs or runs Playwright. pty-probe, terminal-mint-probe,
  ci, migrations and agent-layout-conversion stay on ubuntu-latest and never touch Playwright, so
  they are unaffected by this change (and were already running on 26.04 without trouble).
- e2e.yml today: line 19-20 comment + `runs-on: ubuntu-24.04`; line 58 installs with
  `npx playwright install chromium --with-deps` (uses whatever version is locked, so no edit there).

### Decisions
1. Version range in package.json: `~1.64.1` (patch fixes only), not `^1.64.1`. With a caret, any
   future lockfile refresh would jump to 1.65+, which no longer tests on Node 20. Exact `1.64.1`
   also fine; tilde chosen so 1.64.x bug fixes still arrive.
2. Put `e2e-tests` back on `ubuntu-latest` and remove the pin comment. `create-failure-task`
   already on ubuntu-latest.
3. One PR, two commits (dependency bump, then unpin), so a revert can be partial.
4. It costs one production build (package files aren't on the build-skip list). Ships on its own
   now rather than waiting, unless another build-triggering PR is about to merge the same day.

### Ruled out
- 1.65.0: drops Node 20 testing (needs Node upgrade across workflows; separate card).
- Upgrading but staying pinned to 24.04: leaves the pin to rot; GitHub will retire 24.04.
- Hand-editing package-lock: use `npm install -D @playwright/test@~1.64.1` so npm writes it.
