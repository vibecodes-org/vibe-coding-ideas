### What I decided (recommendation)
1. Stage 1 (now): pin only the `e2e-tests` job to `runs-on: ubuntu-24.04`. One-line change,
   no production build, same image + same Playwright that passed on 30 Oct, so any failure
   that shows up is from the 6 untested merges, not from the tooling.
2. Stage 2 (later, same card): upgrade Playwright to 1.64.1 and put the job back on
   `ubuntu-latest`. Ride along with the next PR that already causes a production build, so it
   costs nothing extra; ship it on its own if none comes within 2 weeks.
3. Failures that surface: test-only fixes (files under e2e/) go in stage 1's PR as separate
   commits. Anything needing an app code change stops and comes back to Nick as a stage on
   THIS card (not a new card), per "keep follow-ups in the card".
4. Close the 6 auto "[E2E] Tests failed on master" cards once master's E2E run is green.

### Ruled out
- Upgrade-only as the first move: costs a production build and changes two things at once
  (new runner + new Playwright), so a failure would be ambiguous.
- Jumping straight to 1.65.0: no longer tested on Node 20; would drag in a Node upgrade across
  all workflows (Node 20 is past end of life; worth its own card, not this one).
- Pinning every workflow to 24.04: the others work on 26.04; pinning them just delays the move.
- Pinning only, forever: GitHub will retire 24.04 eventually (no date announced that I found).
