## Settled by Nick (11 Nov). Don't re-ask
1. No default workflow.
2. A "No workflow" mark on board cards.
3. An agent that picks up a card with no workflow suggests one from the board's existing workflows, using the existing suggestion path, then waits for Nick.

## Facts checked (origin/master 6f3997b, live DB, read-only)
- Workflows attach only when a label with a trigger is added (`checkAndApplyAutoRules`, `src/lib/workflow-helpers.ts`).
- Card badges: `board-task-card.tsx`. `SuggestionBadge` already shows amber "Workflow suggested" when a suggestion is open and no workflow exists. `WorkflowStatusBadge` renders only when `workflow_step_total > 0`. Archived pill is the grey neighbour.
- `workflow_suggestions` (migration 00128): `label_id` is NOT NULL, `source` is limited to 'ai'/'heuristic', and only one open suggestion is allowed per (task, label). Live constraint names: `workflow_suggestions_source_check`, index `idx_workflow_suggestions_open_unique`.
- Keep, Replace and Remove (`src/actions/workflow-suggestions.ts`) don't use the label, so they already work for a suggestion with no label. A suggestion attaches nothing until Keep or Replace.
- `get_task` (`mcp-server/src/tools/board-read.ts`): with no steps and no suggestion it tells the agent to assign itself and start. `claim_next_step` (`mcp-server/src/tools/workflows.ts`) returns `done: true` in the same case. Both already block on an open suggestion.
- Launch prompts (`src/lib/launch-claude-code.ts`, board and task prompts) say "If not, assign it to yourself", which would contradict the new rule.
- Live counts on this board (not archived) of cards with no workflow: Backlog 11, To Do 9, Blocked 1, Done 54.
- The app's own AI fit-check is pay-per-use. The agent that picks up the card runs on Nick's subscription, so the agent does the choosing.

## Decisions taken in the plan (recommendations, need Nick's OK)
- The mark is a grey dashed pill, not amber. It's hidden in Done columns, on archived cards and while a label is still attaching a workflow.
- The agent records its pick with a new board tool `suggest_workflow`. It never calls `apply_workflow_template` itself.
- If Nick clicks Remove (any dismissed suggestion on a card with no workflow), later agents work without a workflow and don't ask again.
- If the board has no workflows, the agent says so and works as it does today.

## Ruled out
- A server-side AI pick when the card is read: costs pay-per-use AI, and a read shouldn't write.
- Faking a label to fit the existing table: misleading data.
- Building card 3e7906ad's tool here: it's separate.

## Overlap with 3e7906ad
That card adds a tool so Nick can say "keep/replace/remove" in a chat session instead of clicking. This card creates a new kind of suggestion. They don't block each other. Once 3e7906ad ships, its resolve tool works on these suggestions too (it goes through the same Keep/Replace/Remove logic), and the "stop and wait" wording here should then mention it. Its plan should know that `label_id` can be empty after this card.
