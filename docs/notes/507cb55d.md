## Decision
Rewrite the hook as:
- `subscribe(notify)`: `const mql = window.matchMedia(query); mql.addEventListener("change", notify); return () => mql.removeEventListener("change", notify);` wrapped in `useCallback([query])`.
- `getSnapshot`: `() => window.matchMedia(query).matches`, `useCallback([query])`. Returns a boolean, so React's
  equality check is stable (no infinite re-render).
- `getServerSnapshot`: module-level `function getServerSnapshot() { return false; }` (same value the server rendered
  before, so hydration is unchanged).
- Remove `useState`, `useEffect` and the eslint-disable. Keep the export name and signature.

Behaviour, before vs after:
- First page load (hydration): before = renders `false`, then the effect flips it. After = React renders the server
  value `false` for hydration, then re-renders with the real value. Same.
- Component that mounts later on the client (dialog opened, client-side navigation): before = one render with
  `false` then a flip (possible one-frame flash, e.g. kit dialog briefly as desktop dialog on a phone). After = the
  right value on the first render. Only improvement; nothing relies on the old flash (checked each caller).
- Resize across a breakpoint: both flip via the `change` event.

## Ruled out
- Keeping useState and moving the read into a lazy initialiser: hydration mismatch risk on the server, and still
  needs the effect for changes.
- A shared module-level cache of MediaQueryList per query (like use-now's single ticker): five callers, cheap API,
  not worth the extra code.
- Touching the PWA install prompt or caller tests that mock the hook: out of scope, they keep passing.

## Tests to add

2. flips when the fake fires a `change` event (wrap in `act`);
