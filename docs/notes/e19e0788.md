# Card e19e0788: starting prompt off the launch line

Cause: terminal/bridge/src/index.js passed PROMPT as the last argv element of `claude` / `codex` (buildSpawnArgs), so `ps` and `pkill -f` saw the card title and text. Board agents were moved off the line in 0.4.1 (card 9b5336c1); the prompt was not.

Fix: `promptOffCommandLine` (session-agents.js) puts the full prompt in the session's private folder (private-files.js, 0700/0600, deleted on exit) as start-prompt.md; argv carries only "Your starting task is in the file <path>. Read that file in full now, then do exactly what it says." Claude also gets `--add-dir=<folder>` so the read is not a permission prompt. All buildSpawnArgs call sites go through `buildLaunchArgs()` in index.js, so the later folder-note and folder-step edits to PROMPT are included.

Checked on the real CLIs (claude 2.1.332, codex 0.169.0), interactive in a PTY: both read the file, start by themselves and act on it; no permission prompt; `pgrep -f <phrase from the file>` lists nothing. Ruled out: `claude --help` has no start-prompt-from-file option for interactive mode; stdin piping puts it in print mode; typing in after start needs readiness detection (fragile); coded form is not decoded by the CLIs.

Decisions:
- Windows, explicit --cmd override and empty prompts are unchanged (no `pkill -f` on Windows; its command line is already budgeted).
- If the file can't be written, falls back to the inline prompt (logged, not silent).
- Visible difference: the first message in the terminal is the short pointer, not the full text. The agent still receives the full text through its first Read. Nick to confirm that is acceptable.
- Launch-link length budget is unaffected (the prompt still travels in the link; only the bridge-to-CLI hop changed).
- Owed: new helper release (not cut here).
