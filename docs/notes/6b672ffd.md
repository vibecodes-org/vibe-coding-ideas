# Card 6b672ffd: mcp-server packaging gap

## Reproduction
Fresh checkout, no root install: `cd mcp-server && npm ci && npm run typecheck`.
Fails: `../src/lib/ai-role-matching.ts` cannot find `ai`, `zod`, `@supabase/supabase-js`;
`../src/lib/ai-helpers.ts` cannot find `@ai-sdk/anthropic`. mcp-server's own install
resolves zod 3.25.76.

## Root cause
mcp-server is not a standalone package. Its tool code imports app files under
`src/lib/` (ai-role-matching, workflow-matching, ai-helpers, step-cost/usage-schema, ...),
and the app imports mcp-server code (`src/app/api/mcp/[[...transport]]/route.ts`,
admin page). Node/tsc resolve bare imports from the IMPORTING FILE's folder, so files
under `src/` always use the ROOT node_modules, mcp-server's own files use mcp-server's.
It only worked because the root install happened to supply everything, and mcp-server's
own zod ^3 was a second, older copy. Declaring `ai` etc. in mcp-server alone would not
help `../src` files, and would create two copies of each package.

## Decision (for Nick)
Standalone install is NOT a supported path; monorepo-only. Made explicit by making
mcp-server an npm workspace of the root: one install, one zod (4.3.6), one lockfile.
Alternative rejected: keep mcp-server separate and duplicate deps (two zod copies, still
broken for `../src`). Alternative not chosen: strip app AI imports from tool code (much
bigger refactor, not needed).

## Changes
- root package.json: `workspaces: ["mcp-server"]`
- mcp-server/package.json: versions aligned to root; adds ai, @ai-sdk/anthropic; zod ^4.3.6
- removed mcp-server/package-lock.json (root lockfile owns it)
- ci.yml comment updated; no scoped install needed
- test: src/lib/mcp-server-packaging.test.ts (failed 5/5 before, passes after)
