# 27ba43a0 - admin report: whole run vs sum of steps

Root cause (confirmed by reading and by a test): in `src/lib/step-cost/report.ts`, `buildStepPerformanceReport`,
each step row is a median of that step's rows, while `wholeRun` is the median of per-run totals over completed runs
that have every current step. A run total adds every row in the run, so redo rounds (extra rows of the same title) are
included; a step median is per step. Medians of sums do not equal sums of medians. Not a calculation error.
Same cause elsewhere: `summary.medianCostPerFinishedRun` (a median of the same run totals, shown in the report header).

Decision (Nick, option C): keep the real figure, relabel "Typical whole run (incl. redos)", add "Sum of steps" row in
both columns. Steps with no figure are skipped; a * marks a short sum and the legend explains it.
Applies to every workflow table (one `StepTable` call per template). Guide: `src/app/guide/admin/page.tsx` had no
whole-run wording; added one sentence. Earlier-version tables never showed a whole run; left alone.

Test: `report.test.ts` "adds up the step rows as a separate line..." failed before the change, passes after.
