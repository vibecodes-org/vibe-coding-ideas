## Plan step (Planner, 14 Oct 2026)

### What the button does today (checked in code, master 6cb5d99)
- The `>_` icon in the task detail header is `LaunchClaudeCodeButton variant="task-icon"`,
  rendered by `src/components/board/task-detail-dialog.tsx` (~L75-85, used at ~L575 read-only and ~L609 editable).
- Its click is `handleLaunch` (`launch-claude-code-button.tsx` ~L431) → `resolveFreshLaunch` → `openInClaudeCode`:
  a `claude-cli://` deep link (external Claude Code / system terminal). Label/title "Launch in Claude Code".
- Hidden below 768px (`if (!isDesktop) return null`, ~L735). Only rendered inside a board
  (`useBoardLaunch()` is null elsewhere).
- The in-app path already exists for tasks: the card ⋯ menu item "Launch in browser terminal"
  calls `handleLaunchInBrowser("claude")` (~L457) → `requestBrowserLaunch` (window CustomEvent,
  `src/lib/terminal/launch-mode.ts`) → the dock's `deliverLaunch` (`terminal-dock.tsx` ~L1987):
  no session for this task → `mintAndDeliver`; a live/recent one → `TerminalTaskLaunchChoice` dialog.
- In-app availability = `isBrowserLaunchAvailable(isTerminalEnabled())`, i.e. `NEXT_PUBLIC_TERMINAL_ENABLED === "true"`.
  The dock itself is hosted by `TerminalDockShell` in `(main)/layout.tsx`, shown on board pages only.
- The dock only works on a Mac (`resolveTerminalPlatform(readPlatformSignals()).supported`);
  other machines get a "coming soon" panel. An unpaired Mac gets the dock's own setup / helper-timeout panels.
- Dock is `z-40`; the task dialog overlay is `z-50` — an in-app launch from inside the dialog
  would open the dock BEHIND the dialog unless the dialog closes.

### Decided (pending Nick's approval)
- Scope: only the task-detail header icon. Toolbar primary and card ⋯ menu unchanged.
- In-app is used when flag ON **and** this machine is a supported Mac. Otherwise today's
  `claude-cli://` launch, unchanged (flag off, Windows/Linux, etc.).
- Pure decision in `launch-mode.ts`: `taskIconLaunchTarget({ terminalEnabled, platformSupported })`.
- Agent stays Claude Code (`handleLaunchInBrowser("claude")`), same as today's icon.
- Task dialog closes when the launch is handed to the dock (flushing pending title/description saves),
  so the dock and any "This task already has a terminal running" dialog are visible.
- Icon unchanged (`Terminal`); tooltip/aria-label becomes "Launch in browser terminal" when in-app.
- Unpaired Mac: no special handling — same dock setup/timeout flow as the ⋯ menu item.
- No mock: the icon looks the same; only behaviour and tooltip text change. A short markdown
  description is attached to the card instead.

### Ruled out (and why)
- A split button / chevron in the header: new control, needs a mock, crowds the header; the ⋯ card
  menu and toolbar dropdown already offer the terminal-window launch.
- Modifier-click (Alt/Shift) for the external terminal: hidden, undiscoverable.
- Flipping the toolbar green primary too: PR #309 (card c4c27987, Option A, approved) defines that
  button as "Launch <agent>" with tooltip "Opens a Terminal window on this Mac"; changing it here
  would contradict an approved design. Offered as a separate decision.
- Following the remembered agent: depends on unmerged PR #309 and was left as Nick's open question there.
- A per-user "default launch destination" setting: bigger than the card asks; possible stage 2.
