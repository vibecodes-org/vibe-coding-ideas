### What the toolbar does today (checked in code, master 6cb5d99)
- `variant="board"` in `launch-claude-code-button.tsx` (~L753-899). Green primary `onClick={handleLaunch}`
  → claude-cli:// (`openInClaudeCode`). Label "Launch Claude Code", no title. Chevron aria "Launch options".
- Flag ON menu: "Claude Code" heading → "In a terminal window" (`handleLaunch`, sub-line "On your computer —

  "In a terminal window" (`handleLaunchCodexDesktop`) → "In the browser" (`handleLaunchInBrowser("codex")`);
  then folder line, Start a new project…, Copy launch command, Set exact folder…, Install guide.
  Flag OFF: single "Open in Claude Code" item.
- A board-level in-app launch = `requestBrowserLaunch` with no taskId → dock `deliverLaunch`
  (terminal-dock.tsx ~L1987): registry still loading → queued and replayed; `entryDecision.kind === "chooser"`
  → chooser (body swap with no tabs, non-destructive overlay with tabs); else `mintAndDeliver`. Same path as the
  dock "+" (which sends a null payload). So the new primary needs NO dock changes.
- The in-browser launch never checks the platform itself; the dock's `beginBrowserLaunch` gate
  (use-terminal-session.ts ~L3083) shows Setup (unpaired Mac) or Coming soon (non-Mac). Pairing =
  localStorage `isBrowserPaired()` (paired-flag.ts).
- No-folder in-app launch: no `cwd=`, bridge runs at the helper's cwd; the prompt carries the
  clone / new-project step. This is how today's "In the browser" item already behaves; not new risk.
- The toolbar loads the button with `dynamic(..., { ssr: false })`, so reading navigator at render is safe.

### Decided (pending Nick's approval)
- One pure rule in `launch-mode.ts`: `defaultLaunchTarget({ terminalEnabled, platformSupported })` →
  "browser" iff both, else "terminal-window". Used by the toolbar primary AND the task-header icon
  (replaces the earlier `taskIconLaunchTarget`). `launchModeOptions(terminalEnabled, platformSupported=false)`
  returns the default target first (so existing callers/tests are unchanged).
- Toolbar primary label unchanged ("Launch Claude Code"); `title` = "Opens the browser terminal on this board"
  (in-app) or "Opens a Terminal window on your computer" (fallback, flag on). Flag off: no title (byte-identical).
- Menu: within each agent group, the item matching the primary's destination comes first (browser first on a
  supported Mac; today's order otherwise). Claude terminal-window sub-line → "Opens a Terminal window on your
  computer". No new "default" chip (avoids clashing with #309's "Your default" agent chip).
- Unpaired Mac still goes in-app (dock shows Setup); terminal window is one click away in the menu.
- Unchanged: "Start a new project…" (still continues into the terminal window after save), Copy launch command,
  Set exact folder, Install guide, chevron aria "Launch options", the task card ⋯ menu, mobile hiding.
- `title` attribute (not the shadcn Tooltip the AI button beside it uses), to match #309's approved design.
- Mock attached to the card: docs/design-launch-default-in-app.html (not rendered in a browser here; the
  cloud session has no Chrome for Playwright).

## Build step (14 Oct)

Built the Rework plan as approved. Decisions made while building:
- `handleLaunchInBrowser` now returns `Promise<boolean>` (true once the request is dispatched, false if the new
  `browserLaunchingRef` guard swallowed a double click) rather than the bare promise, so `onLaunchedInBrowser`
  fires only for a launch that was actually dispatched.
- The flag input to `defaultLaunchTarget` is the existing `browserLaunchAvailable` value (already derived from
  `isTerminalEnabled()`), so there is a single flag read.
- `handleDefaultLaunch` re-reads the platform at click time; `platformSupported` state is read once on mount
  (it only drives labels/menu order).
- AC11 (dialog closes): there is no existing task-detail-dialog test, so it is covered at button level (spy called
  once per launch, never on the terminal-window fallback); the dialog side is a one-line `handleOpenChange(false)`.
  `handleOpenChange` is a hoisted function declaration so the `launchButton` element (declared earlier) can call it.
- Guide pages updated: launching-claude-code (Overview, entry points, dropdown, browser section, Desktop Only) and
  kanban-boards. No other guide page carries the old wording.
- No browser available in this session to render the mock; label/layout unchanged, only hover text, menu order and a sub-line.
