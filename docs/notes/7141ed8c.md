## Side effect found: step helpers are capped by the session limit
- Code comment + commit 1ebd443 (25 Oct): "a helper's own limit can only make it tidy up earlier than its session,
  never later (proved on Claude Code 2.1.310)". Board agents carry 400k but the session's limit is the ceiling.
  (A 24 Oct probe had suggested the opposite; the 25 Oct finding is newer and is what the code and help text say.)
- Circumstantial check, this Mac, last 7 days of transcripts (read-only scan): 782 helper transcripts, peak context
  p50 116k, p90 186k, max 268k; 186 above 150k, 58 above 200k, 0 above 300k; 10 helper compactions all week.
  65 main transcripts: 146 compactions, p90 peak 265k, max 322k. No helper above 300k fits "capped by the session".
- So at 150k roughly 1 in 4 step helpers would summarise mid-step (at 200k about 1 in 13).
- Tried a fresh probe (haiku, session 100k, helper 400k): inconclusive (haiku's own window is 200k and the usage
  figures in -p mode looked cumulative). Not repeated; QA's week-1 check measures it on real work instead.
