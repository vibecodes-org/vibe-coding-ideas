## Stage A (planned in full, approved by Nick 10 Nov)
Builders, reviewers and testers can't start their own helper agents.

Decided (recommended):
- A per-agent setting, not a rule hidden in code. New column `bot_profiles.helper_agents` ('allowed' | 'blocked', default 'allowed'), shown as a second two-option picker under "What it can do" ("Helper agents": "Can start helpers" / "Works alone") on Edit Agent, Create Agent and Admin's agent dialog, plus a "Works alone" badge next to "Read-only". Mirrors how `tool_access` (Read-only) already works end to end.
- 'blocked' adds `Agent` to the subagent's `disallowedTools` (alongside Edit/Write/NotebookEdit for read-only) and adds a short line to the delivered persona's Tools note. Claude only; Codex untouched.
- The persona line is what changes the agents' match tag, so saved agent files re-sync themselves and in-app sessions are told once to Restart/Resume. Without it the tag would not change and stale copies would keep the tool.
- After release: Atlas, Lens and Sentinel (Nick's, by bot id 37e8ffb2, 87e09eb1, da04a09c) set to Works alone. Planner and every other agent unchanged. Built-in templates for new copies of those three start on Works alone.
- No helper (Mac app) release: bridge 0.3.23+ already passes `disallowedTools` through (max 10 names, `Agent` fits its name check).
- The "don't start helper agents" sentence in the Build / Investigate-and-fix step text stays for now.

Ruled out:
- Deciding by role name in code (brittle; roles are free text, other accounts have copies).
- Deny list only, no persona line (tag unchanged, so open sessions and saved files keep the old definition silently).
- A third value on `tool_access` (the two settings are independent: Lens is read-only AND works alone, Atlas is full AND works alone).
