## Decisions taken in the plan (and why)
- No "Starting" comment line needed: every helper is now told to save its write-up with
  save_step_output + work_token, which is the board call the hook reports.
- Hook matches only board calls that carry a work token (save_step_output, add_step_comment,
  add_task_comment), so no other tool input ever leaves the machine.
- Work token is the endpoint's only authentication; endpoint always answers 204 with no body.
- "Can't confirm" also when the claim named no board agent (no persona, or model swapped).
- Review/testing steps found by role words: review, QA, test, audit.
- Persona tag hash gets a version bump so every saved agent copy picks up the hook once.

## Build decisions (10 Nov 2026)
- Hook shape lives twice: `src/lib/workflow/own-agent.ts` (app) and `terminal/shared/own-agent-hook.mjs`
  (bridge), with a drift test in `own-agent.test.ts`. Copied rather than imported because the MCP server
  and helper bundle don't compile each other's TS/JS.
- The bridge keeps `hooks` only when exactly the expected shape for the origin it fetched agents from
  (`TERMINAL_APP_URL` or vibecodes.co.uk). Everything else drops just the hooks; the agent stays.
- Tag bump: `OWN_AGENT_HOOK_VERSION` is mixed into the hashed text in `sessionAgentTag`, for Claude and
  Codex alike (one function), so every saved agent copy reads stale once and re-syncs.
- Synced agent files carry the hook as ONE frontmatter line of JSON (`hooks: {...}`), valid YAML.
  The sync-command "no network tool" tests now strip that `hooks:` line first (it holds the text "http").
- `ran_in_own_agent` is computed in complete_step and fail_step (in-progress steps only). A fail on an
  awaiting_approval step leaves the earlier result. A fail that rescues the step to pending clears the report.
- Web paths: fail/complete/approve clear both hashes, keep the report (it is the record); retry, reset and
  the send-back cascade clear both hashes AND the report. Web skip needs nothing (pending steps hold no tokens).
- The endpoint returns 204 for everything, finds a task_comment's step by task id + in_progress + hash match,
  never replaces the step's own agent's report with another agent's, and skips the write when the same type
  is already recorded (the rate limit). Excluded from the root middleware matcher.
- "Can't confirm" on a Claude step shows its own second line ("this step wasn't sent to its own board agent")
  and no Codex tag; the Codex wording and tag appear only when the executed model is a Codex one.
  The mock showed only the Codex case; this is the one wording the mock did not cover.
- Guide pages: searched; none describes the Persona/Execution lines or the compliance alert, so none changed.
  Changelog entry added.
- Helper version / MINIMUM_RECOMMENDED_HELPER_VERSION NOT bumped in this PR: the recipe bumps the minimum
  only after the notarized release exists. RELEASE ORDER MATTERS: an app deploy before the helper release
  makes every in-app review/QA step read "not confirmed" and alert (old helpers drop the hook).
