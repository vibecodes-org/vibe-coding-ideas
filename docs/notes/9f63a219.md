# 9f63a219: what recent coding-agent research means for our agent set-up

Research step, 10 Nov 2026 (Planner). Full write-up is the step output on the board; this file is the short trail.

## Decided (recommendation, awaiting Nick)
- Keep model and effort per role as they are (plan and review on the top model at medium effort, build and test on the mid model). Live tier settings checked 10 Nov.
- No hard block on test edits: 72 of the last 97 merges to master changed an existing test file and 17 removed more than 20 test lines, so a block would fire on most changes. Instead, give the reviewer a list of changed or removed tests, checked against the tests the plan says will change.
- No second review pass. Instead the reviewer reads the change before the builder's own account and treats that account as unchecked claims.
- Cap code-review send-backs: after the second send-back, ask Nick instead of looping. Data (60 days, completed reviews): 175 runs; 90 passed first time, 58 needed one send-back, 11 needed two, 16 needed three or more (up to 8).
- Turn off the Agent tool (starting helpers) for the build, review and test agents. Claude Code lets a subagent start its own subagents, three layers deep by default (docs checked). Today only the step wording says "don't start helper agents".
- Balla Bot: trim its always-loaded rule file (74k characters) using the "would Claude get this wrong without it?" test. Needs the bot's yes as well as Nick's.

## Ruled out
- "Write tests first" changes: the build and fix steps already make the builder run the affected tests and then the full suite. The study behind the finding used small local models.
- Rewording roles to drop "expert": the five built-in agents don't use it. The client agents that do are left alone (that wording is the client's).
- Separate protection against malicious cards on VibeCodes: Nick writes the cards. Balla Bot's inbound messages are the real exposure, and it already has automatic blocks; an audit is optional.
