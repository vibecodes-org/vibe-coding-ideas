# Card 23f65c41: agents bypass the attached workflow

Working notes for the Plan step (12 Nov 2026). Later steps read this.

## The problem in one line
An agent can ignore a card's workflow, build the change itself and move the card to
Verify or Done with every step still unrun. The board server says "success" and nobody
notices. An agent that creates a card also isn't told that a workflow got attached.

## What I checked (live code on master fc729e51, read-only production queries)
- `moveTask` (mcp-server/src/tools/board-write.ts ~466) never looks at the workflow. It
  reads the target column's `title, is_done_column`, moves the card, logs "moved", and
  returns `{ success, column, position }`.
- `createTask` (same file ~77) runs the label auto-rules (`checkAndApplyAutoRules`, which
  returns nothing) and returns `{ success, task, labels }`: no word about a workflow.
- `manage_labels` add_to_task (mcp-server/src/tools/labels.ts ~66-102) has the same gap.
- `getTask` (mcp-server/src/tools/board-read.ts ~300-475) builds `workflow_instruction`
  inline: failed-step text, pending-steps text ("Do NOT begin implementation directly..."),
  open-suggestion text, else `noWorkflowInstruction` (mcp-server/src/lib/no-workflow.ts).
  It uses `pickCurrentRunKey` / `pickNextOpenStep` (src/lib/workflow-current-run.ts).
- Tool descriptions for create_task / move_task (mcp-server/src/register-tools.ts ~440,
  ~474) say nothing about workflows.
- Nothing in code moves a card to Verify/Done for the agent; agents do it themselves.
  Web drags go through server actions, not move_task, so a guard in move_task affects
  agents only, never Nick's own drags.
- Columns: Verify has `is_done_column = false`; Done has `true`. Verify must be matched by
  title.
- The guide lists move_task as "Move a task to a different column" (src/app/guide/
  mcp-integration/page.tsx:329). Still true; no guide change strictly needed.

## Live data (approximate: agent vs web moves matched by board + time, last 60 days)
- To Done by agents: 59 with no step ever started, 16 midway, 302 clean.
- Those 59 were mostly batch tidy-ups where the agent wrote a reason comment each time
  (closing duplicates or stale cards with Nick's OK). Early close with a reason is a real,
  legitimate need and must stay possible.
- To Verify by agents: 0 never-started, 78 midway, 115 clean. Midway-to-Verify is the
  normal pattern (card goes to Verify after release, before the final check step), so it
  must not be blocked.
- 54 approval-gated steps were skipped in 60 days; none matched an agent call. No
  evidence agents abuse skip_step, so it is left alone.

## Decisions (recommended; Nick approves at the Plan gate)
1. Move to Done with open steps: refuse, unless the agent passes a short reason. With a
   reason the move goes ahead and the reason is posted on the card as a comment.
2. Move to Verify: refuse only when the workflow was never started (and no reason given).
   Midway moves go ahead, with a reminder listing the steps still to run.
3. Early close leaves unrun steps exactly as they are (not marked skipped), so the card
   still honestly shows what never ran.
4. Leave skip_step alone (no evidence of misuse; agent-safety fixes should add nothing new).
5. No visible "closed early" badge in this change. If wanted, a later stage with a mock.

## Ruled out
- Per-card "enforcement" switch: a new setting Nick would have to manage; the guard above
  covers the real failure without one.
- Blocking every column move until steps finish: breaks the normal Verify-before-final-
  check pattern and the In Progress auto-move.
- Auto-skipping steps on early close: hides what never ran.
- Telling web drags apart from agent moves in the activity log: not needed once the guard
  sits in the agent-only path; the reason comment is the record.

## Stages
- Stage 1 (this plan): board-server only. Tell agents about attached workflows when they
  create or label a card; guard move_task. User-facing change: NO (the only thing Nick
  sees is a normal comment carrying the agent's reason).
- Stage 2 (optional, only if Nick wants it): a visible marker on cards closed with steps
  unrun. Needs a mock.

## Build notes (stage 1)
- Instruction text moved into `mcp-server/src/lib/workflow-instruction.ts` (one builder for
  get_task, create_task and add_to_task); `workflow-reply.ts` loads steps and suggestions for
  the two write paths. Wording is unchanged, so get_task replies are identical.
- move_task gained `close_reason` and an optional `work_token` (so the early-close comment
  is written in the step agent's voice, the same way add_task_comment does it). The comment
  goes through `addTaskComment`. If the comment fails after the move, the reply carries a
  `warning` rather than failing, since the card has already moved.
- Guard applies only on a real column change. Done uses the column flag; Verify matches the
  title (trimmed, case-insensitive).
- No migration. The MCP server deploys with the web app (remote route); local stdio users
  need to rebuild/restart their server to pick it up.
