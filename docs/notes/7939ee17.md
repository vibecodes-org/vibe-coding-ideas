## Facts from code.claude.com docs (fetched 14 Oct 2026)
- sub-agents: "Claude Code watches `~/.claude/agents/` and `.claude/agents/`. When you add or edit a subagent file on disk … the next delegation uses the updated definition, with no restart needed." Exception: "The watcher covers only directories that existed when the session started". So the memory note "new agents need a fresh session" is only true when the agents folder didn't exist at session start.
- Agent files support every field our `--agents` JSON uses: `name`, `description`, `model` (alias or full model id), `effort` (low…max), `disallowedTools`. Body = system prompt. Filename needn't match `name`.
- Precedence on a name clash: `--agents` (2) beats project `.claude/agents/` (3) beats `~/.claude/agents/` (4). So a VibeCodes-launched session keeps using its `--agents` copy.
- Agent tool has no system-prompt parameter (only per-call model/effort), so a file or `--agents` is the only way a persona becomes a subagent's real system prompt.
- cloud-environments: repo `CLAUDE.md`, `.claude/settings.json` hooks, `.mcp.json`, `.claude/agents|skills|commands` carry into cloud; `~/.claude/*` and user MCP servers don't. Connectors work without allowlisting. Custom network level takes an "Allowed domains" list (+ optional default list). A setup script runs before Claude Code starts, is cached as a filesystem snapshot (~7 days), and Anthropic documents using it to write `~/.claude/CLAUDE.md` for personal preferences.
- hooks: SessionStart `mcp_tool` hooks are skipped at launch (MCP servers not ready yet); only `command` hooks run then. `$CLAUDE_CODE_REMOTE` is "true" in cloud.

## Decisions (pending Nick's approval)
1. **Delivery route: an on-demand "sync" that writes the board's agents as untracked `.claude/agents/vc-*.md` files**, triggered by `claim_next_step` itself when the named subagent isn't offered. New MCP tool (working name `sync_board_agents`) returns a 5-minute signed download link and one shell command; the orchestrator runs the command (curl → tar into `.claude/agents/`), Claude Code's watcher loads them in seconds, the orchestrator spawns `vc-<agent>-<id>-<tier>`. Same definitions as the in-app `--agents` payload (same builder), so the tags match.
   - Why a download, not file text in the MCP reply: the model would have to retype ~70 KB of personas with the Write tool (expensive, close to Claude Code's MCP output cap, and retyping is exactly where personas get edited). curl writes the server's bytes untouched.
   - Ruled out: SessionStart command hook (no way to authenticate to VibeCodes without a new personal API token; blocked by the cloud network anyway; would run for every contributor of the public repo). SessionStart `mcp_tool` hook (skipped at launch). Cloud setup script (cached up to 7 days so definitions go stale; network secrets don't apply to it). `claude --agents` wrapper for own terminals (needs its own auth, doesn't help cloud).
2. **Keep prompts out of git.** Commit only `.claude/agents/.gitignore` (contents: `vc-*.md`) in this repo — it also makes the folder exist in every fresh clone, which the watcher needs. In any other repo the sync command adds `.claude/agents/vc-*.md` to `.git/info/exclude` (local, never committed).
3. **Cloud network:** Nick switches his cloud environment to Custom network, keeps the default list, and adds `vibecodes.co.uk`. Without it, sync fails cleanly and steps run on today's general path.
4. **Board tools in cloud:** the claude.ai VibeCodes connector (already proven here). No committed `.mcp.json`.
5. **Personal instructions:** Nick's cloud environment setup script writes `~/.claude/CLAUDE.md` (documented by Anthropic; stays out of the public repo). Nick pastes his own text; not stored by us.
6. **Signing:** reuse `TERMINAL_SESSION_SECRET` through a key derived for this purpose only (HMAC of a fixed label), in a new app-side module. No new env var, no change under `terminal/`, no relay deploy.
7. Local stdio MCP mode: not supported in stage 1 (clear message). Codex: out of scope (card e16d69e8).
