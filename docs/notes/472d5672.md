## Nick's approval (12 Oct, 07:54): two binding changes

### Change 1: convert every old-layout agent in one go (replaces "convert when opened and saved")
- **Why:** Nick wants every agent in the new layout now, not agent by agent. Scope: this board's, the platform's and all other copies.
- **Size (live read, 12 Oct):** 155 agents have instructions. 136 are in an old layout (115 with `## Goal…` headings, 21 inline-marker). By owner: 24 Nick, 23 platform, 89 other sign-ups. 19 are in neither layout, including this board's Planner, and are left untouched. 1 has an empty prompt. About 300K characters in all, max 4,970 per agent. These are SQL approximations; the dry run gives the real figures.
- **How it runs: a GitHub Actions job that runs a TypeScript script against production.**
  - New `workflow_dispatch` workflow `agent-layout-conversion.yml`, running `scripts/convert-agent-layouts.ts` with the production secrets CI already has (`PROD_SUPABASE_URL`, `PROD_SUPABASE_SERVICE_KEY`, used by migrations.yml).
  - Modes: dry-run / apply (needs confirm=CONVERT) / verify / restore (needs confirm=RESTORE).
  - The pure logic lives in `src/lib/agent-layout-conversion.ts`, the same converter as the editor, and is tested there.
- **Ruled out:**
  - **A migration with literal UPDATEs.** The repo is PUBLIC (vibecodes-org/vibe-coding-ideas). That would publish 89 other people's agent prompts, and 300K of text would also have to pass through the agent's own tool calls.
  - **A PL/pgSQL port of the converter.** It duplicates the logic, and verifying it needs the TS converter run against production anyway.
  - **A local script.** `.env.local` points at a preview database, not production. There's no production key locally, and pulling one isn't appropriate.
  - **A super-admin button in the app.** It's permanent product surface for a one-off job, and it needs Nick's login.
- **Public repo rule:** no prompt text in the repo, CI logs or artifacts. The script prints ids, owner group, layout, lengths and counts only. `--show` full text is allowed only for platform-owned agents, whose prompts are already public in migrations.
- **Backups:**
  - Migration `00186_bot_profile_prompt_backups_pre_layout_conversion.sql` snapshots ALL rows under reason `pre-layout-conversion-00186`, following the 00148/00174 pattern.
  - In apply mode, the script also inserts a fresh backup under the same reason for any row whose text changed since the snapshot.
  - Restore uses the latest backup per agent.
- **Safety:**
  - Each update is compare-and-set on `updated_at`, so an agent edited mid-run is skipped, not overwritten.
  - Each row passes three checks, or it's reported as failed and left untouched: (1) the new text parses as the new layout; (2) the parsed fields equal the converted fields; (3) no words are lost (old-layout markers and an exact "You are a/an <role>." prefix excepted).
- **Re-runnable:** converted text parses as the new layout, so a second apply converts 0.
- **Restore:** script restore only puts back agents still exactly as the conversion left them. A blunt SQL restore is documented in the migration header, as a last resort.
- **Converter fixes found while specifying this:**
  - The legacy markdown parser drops any text before the first `## Goal`-style heading. The converter keeps it, as the start of the goal.
  - The legacy "You are a X." strip could eat a real first sentence. The converter strips it only when it matches the agent's own role exactly.
- **Fingerprints:** every converted agent's in-app fingerprint changes. Every browser-terminal session started before the apply must be relaunched before the next step is claimed, including the one orchestrating this card. Otherwise steps quietly run on general helpers. This is release step 4.

## Build step (Atlas, 12 Oct 2026)

### Decided while building
- **Editor remounts instead of a `templateFields` prop.** The create/admin dialogs set the stored text from the template and bump a `key`, so `AgentInstructionsEditor` just parses `value` on mount. Props are `value`, `onChange` and an optional `role` (needed so an old "You are a <role>." opening is recognised; the plan said "no role prop").
- **Converter parser option.** `parsePromptToFields(text, { role })` is the converter mode (keeps text before the first heading, strips the role opening only when it equals the agent's role). Without the option it behaves exactly as before, so old tests and any display use are unchanged. The display parser (`parseInstructions`) uses converter mode too.
- **First sentence ends at . ! or ? followed by a capital, digit, quote, bullet or the end.** If that sentence is over 300 characters it is not made the one line; the whole goal goes to the job (e.g. the platform Audio Designer).
- **Three checks live in `verifyConversion`** (reads back as new layout; fields equal; no words lost, ignoring old markers/headings and an exact own-role opening). Real check: all 23 platform agents (public prompts) pass in a local dry run.
- **A prompt that already contains a new-layout heading counts as new**, even if it also has `## Goal`. It is left alone. The three checks are defence in depth; a unit test forces the failure path with a mocked check.
- **Import from file leaves tool access alone when the file says nothing** (app `importAgentFromSkill` and MCP `import_agent_skill`), so a round trip cannot reset a Read-only agent.
- **No tool access for kit fallback in MCP** (it creates agents with no prompt anyway); app kit fallback uses the template's tool access (Code Reviewer = Read-only). Library copies keep the source's setting.
- **`createBot` no longer fills tags from the role.** `getDefaultSkillsForRole` has no remaining callers in app code (left in place).
- **Dead profile dialogs deleted:** `create-bot-dialog`, `edit-bot-dialog` (also dead: nothing imported them), `bot-management`, `prompt-builder` and its test.
- **Chip list:** `ROLE_TEMPLATE_CHIPS` (Planner first, Security Engineer under More). Copywriter / Content has a template but, as today, no chip. Shared `RoleTemplateChips` component used by create and admin screens.
- **Delivery:** `agentPersonaBody` is applied on both sides of the fingerprint (claim, session definition, claim hint). A bot with an empty prompt gets no note, so it still falls through to `get_agent_prompt`. `get_agent_prompt` returns `tool_access` and leaves `system_prompt` raw.
- **Bridge:** `disallowedTools` accepted only as 1-10 names matching `/^[A-Z][A-Za-z0-9_]{0,63}$/`; anything else drops the whole payload (launch without agents). Needs helper 0.3.23 to take effect.
- **Conversion job** (`src/lib/agent-layout-conversion.ts`, `-store.ts`, `scripts/convert-agent-layouts.ts`, `.github/workflows/agent-layout-conversion.yml`): built with esbuild (already installed via vite) then run with node, because there is no tsx and Node 20 cannot run extensionless TS imports. apply/restore run in a separate job behind `environment: production`; dry-run/verify are read-only. `--owner-id` optional for the "owner" group. `--show` only for platform-owned agents. Smoke-tested the bundle against a local fake REST server (dry-run, apply, verify, show, refusal).
- **Verify mode** judges only agents still exactly as converted; agents edited since are counted as skipped-edited. After apply a second apply converts 0.
