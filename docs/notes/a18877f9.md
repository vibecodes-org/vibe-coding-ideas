# Card a18877f9: sessions summarise their memory too often when picking up cards

Investigated 13 Nov 2026. Result: not a code bug. A setting change did it.

## Cause (confirmed with data)
- Live site default `terminal_auto_compact_default` (platform_settings) is {"window":150000}, updated 12 Nov 2026 06:31 UTC.
  It was 300000 before (set 24 Oct, migration 00198). Card 7141ed8c deliberately lowered it ("coordinator sessions summarise
  themselves sooner"); the code change in #461 only added 150k to the choices, the value itself was set in Admin afterwards.
- The helper launches Claude with `--autocompact 150000` (terminal/bridge/src/auto-compact.js, launchFlags in index.js)
  for every user who has no own value (all users: none).
- Evidence from Nick's Mac, all session transcripts for this repo and its worktrees (compaction events):
  - 9-11 Nov: 3, 6, 7 compactions a day, each at a median of ~267k tokens.
  - 12 Nov: 26 compactions, median 117.7k. 13 Nov (so far): 16, median 117.8k.
  So compactions per day roughly quadrupled and each now happens at ~118k (the 150k limit minus room
  Claude Code keeps for the summary).

## Ruled out: heavy board replies
- get_board for this board: ~14k characters (~3.5k tokens). get_my_tasks (all boards): ~7k chars. get_task (short form): ~6k chars.
  Slimmed in #382 (24 Oct). MCP changes since 1 Nov (#463 next-card hint, #467, #457 SDK v2) add only a few lines per reply.
- Picking up 5 cards is many small calls (claim, get_task, step write-ups) on top of Claude Code's own start-up context
  (system prompt, tools, agents), so a 150k ceiling is reached quickly. That is the ordinary cost of the lower ceiling,
  as predicted in docs/notes/7141ed8c.md ("at 150k roughly 1 in 4 step helpers would summarise mid-step").

## What I did not change, and why
- The value is stored data and an approved decision (Nick's). No code defect exists to test, so no regression test was
  written. Changing the stored value is Nick's call, done in Admin with no build.

## Options for Nick
1. Raise the site default in Admin to 200k (the 7141ed8c fallback; about 1 in 13 helper steps would still summarise) or 300k (back to before).
2. Keep 150k and accept more summaries. (Per 7141ed8c the limit also caps step helpers, so it cannot be 150k for coordinators only.)
3. Set your own value in Settings (overrides the site default for you only), or type /autocompact in a session.

## Decision
- Nick chose 200k and saved it as the site default in Admin on 13 Nov 2026 (06:33 UTC). Sessions pick it up when started or resumed.
- If 200k still summarises too often, 300k is the next step in the same setting.
