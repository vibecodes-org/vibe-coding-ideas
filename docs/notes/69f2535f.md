## Root cause (three parts, one origin)
Codex support (#264, commit 737485e, merged 6 Sep 2026) added `agent` to the rows and `AgentChip` to the chooser, but:
1. `terminal-session-chooser.tsx` never reads `agent` when choosing which Recent rows to show (`visibleRecentHere` / `visibleRecentElsewhere`, ~line 287). The picker only feeds `onStartNew`.
2. `RecentRow` never renders `AgentChip` (only `LiveRow` does, ~line 617).
3. `deriveChooserSections` in `src/lib/terminal/chooser-data.ts` predates Codex in two rules that ignore the agent:
   - the "one row per folder for rows with no conversation id" collapse keys on `cwd` alone (`seenIdlessCwd`, ~line 320). Every Codex row has no conversation id, so a newer id-less Claude row in the same folder (or a newer Codex row) eats it. Codex rows in one folder should still collapse to one (Codex Resume = "most recent Codex conversation in this folder"), but only against other Codex rows.
   - `RECENT_MAX` (10) is one shared cap, so a burst of Claude sessions pushes every Codex row out before any filter could see it.
   Parts 1 and 2 are what Nick saw. Part 3 is why a filter-only fix would show an EMPTY Codex Recent list on today's data.
The gap has existed since 6 Sep 2026 (first Codex session in the table: 6 Sep 19:37 UTC).

## Fix plan (see the step output for full detail)
- `chooser-data.ts`:
  - id-less collapse key → `rowAgent(r.agent) + "\u0000" + cwd` (one id-less row per folder PER AGENT).
  - cap → `RECENT_MAX` per agent (newest-ended first, order unchanged). For a single-agent user the result is byte-identical to today.
  - new pure export `filterRecentByAgent(rows, agent?: LaunchAgent)` → `agent` undefined returns rows unchanged; otherwise keeps rows where `rowAgent(r.agent) === agent`.
  - `recent`, `recentHere`, `recentElsewhere` stay unfiltered by agent (task dialog matching, `?resume=` lookup and header counts read them).
- `terminal-session-chooser.tsx`: `const recentAgent = agent && onAgentChange ? agent : undefined;` then wrap both `visibleRecentRows(...)` calls in `filterRecentByAgent(..., recentAgent)`. Add `<AgentChip agent={rowAgent(row.agent)} />` in `RecentRow` right after the idea chip, exactly as `LiveRow` does.
- Prototype of the chooser-data change on the live-shaped data: Claude tab shows the same 10 rows as today; Codex tab shows 1 row (`4ebac80f`, newest Codex in that folder).

## Ruled out / kept out
- Filtering inside `deriveChooserSections` by the picked agent: would hide rows from `findTaskSessionMatch`, the `?resume=` landing lookup and the header count. Filter at display only (same reasoning as `visibleRecentRows`).
- Per-task launch dialog (`terminal-task-launch-choice.tsx`): already shows the matched row's agent chip; its picker only governs "Start fresh". Not touched.
- My sessions panel (`terminal-my-sessions-panel.tsx`): running sessions only, already chips every row. Not touched.
- No placeholder text when the picked agent has no Recent rows: the existing rule is "empty section = no heading, no placeholder"; adding one would be new UX Nick hasn't approved.
- Entry decision (`entry-decision.ts`) reads raw rows and has no per-folder collapse: unaffected.

## Side effects the reviewer/QA should expect

So the header pill's "N recent" can go up (today's data: 10 → 11) and a task whose last session was Codex can now get the task dialog's "recent session" offer. Both are correct counts/offers, not new UI.
