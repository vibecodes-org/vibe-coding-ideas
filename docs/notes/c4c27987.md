## Rework 15 Oct (merge with #361)

Card 5a24479e (PR #361) landed after #309 was built: on a supported Mac with the terminal flag on,
the board primary opens the in-app browser terminal; elsewhere a Terminal window. #309 was merged
with master (merge commit, no rebase) and reconciled as follows.

- **Primary button:** label stays `Launch {AGENT_LABEL[rememberedAgent]}`. Click re-reads the
  platform at click time (like #361's `handleDefaultLaunch`): target `browser` →
  `handleLaunchInBrowser(rememberedAgent)` (the in-flight guard lives inside it; failures toast
  "Couldn't start the browser terminal"); otherwise Codex → `handleLaunchCodexDesktop()`, Claude →
  `handleLaunch()`. A separate `handlePrimaryLaunch` was added so the task-header icon keeps using
  `handleDefaultLaunch` and stays Claude-only.
- **Title:** #361's exported `BOARD_PRIMARY_TITLE_BROWSER` / `_WINDOW`, none with the flag off.
  #309's "Opens a Terminal window on this Mac" is dropped.
- **Menu:** inside `[rememberedAgent, otherAgent].map`, each group renders its two items in
  `launchModeOptions(true, platformSupported)` order. Kept: "Your default" chip, footer
  "Default agent: X · Switch to Y", "More ways to launch" chevron label, agent-aware Copy/Install.
  Claude's terminal-window sub-line is #361's `CLAUDE_WINDOW_SUBLINE`.
- **Guide:** launching-claude-code page merges both texts; kanban-boards needed no change.
- **Migration:** renumbered `00177_terminal_agent_toast_seen` to `00193_terminal_agent_toast_seen`
  (master was at 00192); comment references and the spec updated. Not applied anywhere; the
  real-schema run is still owed by the release session.
- **Docs:** both design pages carry a note that #361 overrides the primary's destination.
- **Decision for Nick:** the "Switch to" footer and chip are unchanged from the approved mock; the
  only visible difference from the mock is the menu item order on a supported Mac (browser first),
  which comes from #361.
