# Card 745c89af: board hides cards past 1,000 rows

## Cause
The database returns at most 1,000 rows per request, silently. The board page
(`src/app/(main)/ideas/[id]/board/page.tsx`) and the realtime refetch
(`fetchBoardRefreshData` in `src/lib/board-refetch.ts`) each loaded every card of
the board (archived included) in one unpaged query ordered by position, so on a
board with 1,045 cards the last 45 by position vanished. No error anywhere.
Starts the day a board passes 1,000 cards; nothing before that is affected.

## Reproduction
Test `board-refetch.test.ts` > "board with more than 1,000 cards": a fake database
that caps answers at 1,000 rows (`src/test/capped-supabase.ts`). Failed (1000 of
1045) before the change, passes after. Same for the label rows and MCP get_board
(`board-read.test.ts`).

## Decision
One helper, `fetchAllRows` in `src/lib/db-helpers.ts`, pages with `.range()` until
a short page comes back. Every paged query has a total order (a unique `id`
tie-break) so pages cannot repeat or skip rows. Not chosen: loading archived cards
only on "Show archived" (changes what the page loads and the archived toggle; paging
is needed anyway). Can be a follow-up if the board gets slow.
No screen changes, no stored data touched.
