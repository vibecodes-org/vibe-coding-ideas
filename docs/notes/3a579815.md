# 3a579815 — in-app terminal: load every agent the board's workflows use

Card: "In-app terminal: give every session all the agents the board's workflows use, not just the ones with a step waiting".
Planner step: 12 Oct 2026. User-facing change: NO (no screen changes; sessions just carry more agents). No mock.

## Where things are
- Selection today: `src/app/api/terminal/session/agents/route.ts` — reads `task_workflow_steps` in pending/in_progress/failed with `.limit(1000)`, keeps unique (bot, tier) pairs.
- Builder + size cap: `src/lib/terminal/session-agents.ts` (`buildSessionAgents`, `SESSION_AGENTS_MAX_BYTES = 200_000`, `definitionFor`, `sessionAgentClaimHint`).
- Bridge side: `terminal/bridge/src/session-agents.js` (`validateSessionAgents` re-serializes the same five fields in the same order and drops EVERYTHING if over 200,000 bytes). Bridge fetch timeout is 5 s (`SESSION_AGENTS_FETCH_TIMEOUT_MS` in `terminal/bridge/src/index.js`).
- Claim side: `mcp-server/src/tools/workflows.ts` ~line 1250 builds `sessionAgentClaimHint` from step.bot_id + step.model_tier + owner's tier map + skills text. Unchanged by this card.
- Role → agent matching used by apply_workflow_template: `src/lib/ai-role-matching.ts` `matchRolesWithAiOrFuzzy` (exact, then AI, then fuzzy `buildRoleMatcher` from `src/lib/role-matching.ts`). Candidates = `idea_agents` joined to `bot_profiles` with a role. AI results are cached per board in `idea_role_match_cache` (written by `src/actions/idea-agents.ts` role-coverage).
- Template steps (`workflow_templates.steps` jsonb) only carry: title, role, model_tier, description, deliverables, requires_approval. No agent id. Auto-rules (`workflow_auto_rules`) only point at a template of the same board, so "all the board's templates" covers them.

## Decisions (pending Nick's approval of the plan)
1. Source of the extra agents: the board's workflow templates (option 1 on the card). Role -> agent resolved WITHOUT any AI call at launch: exact role match (all allocated agents with that exact role), else the board's cached match for that role if that agent is still allocated, else the fuzzy matcher. Tier = template step's model_tier (anything not frontier/standard/cheap = untiered, same as the claim side).
   - Why no AI call: the bridge waits only 5 s for this answer, and an AI match can take up to 90 s and costs credits. A missed or extra optional agent is harmless (tags are exact per bot+tier), a timed-out fetch loses ALL agents.
   - Ruled out: every allocated agent at every tier (YCS over the limit; also lists agents/tiers that no step will ever use).
2. Priority: agents with a waiting step ("must") always first, built exactly as today (full skills, then the existing names-only fallback). Template-only agents ("optional") fill the room left, one at a time, most-used first, full skills only; one that doesn't fit is skipped, never shrunk. Final safety: if even the names-only "must" set is over, include "must" agents one at a time (most waiting steps first) instead of returning nothing.
3. Size limit stays 200,000. Largest board is ~96 KB. Raising it needs a helper release and isn't needed. App-side packing guarantees the bridge's all-or-nothing check never trips.
4. No bridge or helper change. No database change. No MCP / claim_next_step change. Fingerprints unchanged because `definitionFor` is unchanged; only the input list changes.
5. Fix the 1,000-row cap in the same change: page through claimable steps (ordered by id, 1,000 per page, stop on a short page, hard cap 20 pages) so "must" is exact.
6. Codex: same route and same builder; covered automatically. Codex gets one temp role file per agent; no count limit in our bridge code; payload ceiling is the same 200 KB check. Each extra agent adds one line to Codex's spawn-tool agent list, same as Claude's Agent tool list.

## Known gap (accepted unless Nick says otherwise)
- Mid-session, hand a step directly to an allocated agent that NO template on the board uses (or at a tier no template uses) -> still needs a resume. Today every agent on this board is used by a template, so it doesn't bite here.
- A template role that only an AI match would resolve (not exact, not cached, fuzzy misses) won't be preloaded.
