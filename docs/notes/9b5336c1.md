# Card 9b5336c1: in-app sessions killed by other agents' pattern kills

## Root cause
`pkill -f <text>` matches a process's whole command line. The bridge
(`terminal/bridge/src/index.js`, `sessionAgentArgs` -> `serializeSessionAgents`
in `session-agents.js`) starts Claude as `claude ... --agents <JSON of every
board agent's prompt>`, a 31k-92k character command line. Any helper agent that
runs `pkill -f "<words that appear in an agent prompt>"` (26 Nov 2026: pytest,
http.server, tools/e2e.sh) therefore SIGTERMs the session (exit 143). The
launch prompt (first launch only, `buildSpawnArgs`) is on the line too. Resumes
carry no prompt, so the 26 Nov kills (all `--resume`) came from `--agents`.

Reproduced with a harmless dummy: a `node -e` process given a long marker
argument is matched by `pgrep -f <marker>` (same matcher as pkill); only that
pid was killed.

## What the CLIs accept (Claude Code 2.1.332, tested)
- `--agents <file>`: refused in interactive mode ("a file path only with --print").
- `--settings` with an `agents` key: ignored (agents not loaded).
- `--add-dir` with `.claude/agents`: not loaded.
- `--plugin-dir` with `agents/*.md`: loads, but as `plugin:vc-...` (renamed) and
  plugin agents can't carry the per-agent hooks (attest hook, card 24936814).
  Rejected: would change names the workflow prompts use.
- Codex: agents already travel as role files in a temp folder; argv has only paths.

## Decision
Keep `--agents` inline but write the JSON with `\uXXXX` escapes
(`escapeJsonText`). The CLI parses identical text; the readable words are gone
from the command line. Everything escaped when it fits under ~700 KB, otherwise
every other character (still breaks any 3+ char pattern; stays under macOS's 1 MB
argument limit). Only the escape of 1-2 character patterns is not covered.

## Review follow-ups
- Windows gets plain JSON (32,767-char command line limit, no `pkill -f`).
- The every-other-character fallback works by code point, so emoji are never split.
- Nick chose to leave the first-launch prompt as it is for now.

## Stage 2 (27 Nov 2026, Nick's rework)

### What the CLIs accept (Claude Code 2.1.332, Codex 0.169.0 — tested with the real CLIs, interactive via a PTY)
- `--settings <file-or-json>`: a file path works, hooks in it run (command hook and
  the http hooks to the bridge both fired in a real interactive session).
- `--append-system-prompt-file <file>`: works (print and interactive); note text
  reached the model. Same effect as `--append-system-prompt`.
- `--agents`: file only with `--print` (error string confirmed in the binary), so still inline.
- Codex `-c developer_instructions="..."`: value is parsed as TOML, so a basic string
  of `\uXXXX` escapes works (secret word came back). Codex has no file flag for it
  that appends (a base-instructions file would replace them).

### Decisions
- New `private-files.js`: one 0700 folder per session, 0600 files, removed on exit
  and in finishShutdown; shares the folder the Codex role files already used.
- Claude: hook settings (hold the secret URL) -> `peer-hooks.json`; messaging note
  -> `peer-note.txt`; argv carries only the two paths. Secret is no longer in `ps`.
- Codex: note is passed as `\u`-escaped TOML (tomlEscapedString). The hook command
  (`curl ... $VIBECODES_PEER_HOOK`) is the same fixed text for every session and holds
  no secret (the URL is in the environment), left as it was.
- Windows, Claude: `--agents` can't be a file. When the JSON exceeds the room left
  under 32,767 chars, the biggest prompts go to files in the private folder and the
  agent keeps a short stub ("read this file first, follow it"); every agent still
  loads under its own name. If even stubs don't fit, the last agents are left out
  and the terminal says which. Mac/Linux unchanged (coded inline).
- Not closed: the pure-hex/1-2 character pattern gap in the coded agents (a pattern
  like `0069` still matches `i`). Only a file would close it and Claude refuses
  one for interactive `--agents`. Nobody pkills such text; left as is.
- A Windows stubbed agent must read its file with the Read tool: an agent that has
  Read disallowed would not get its instructions (none do today; disallowedTools is
  Edit/Write style).

### Proof
Real PTY run with the real CLI: secret and note text absent from `ps` args, hooks
reached the bridge listener (UserPromptSubmit, Stop), the model obeyed the note
file, folder removed on exit. Tests: session-agents-stage2.test.js,
private-files.test.js, peer-bridge.test.js (secret not on argv).
