Choose when a terminal session tidies up its memory

A new pair of settings, one for Claude and one for Codex. When a session's memory reaches the size you pick, it summarises the conversation so far and carries on, so every later action re-reads less. It applies to new and resumed in-browser sessions. Each new item has a blue dashed outline; everything else is today's screen, unchanged.

1. Settings → Model Tiers → Terminal sessions NEW ROWS

Each new row sits straight under its agent's existing rows. It uses the same strip of buttons as "Starting effort", with the same "Default" button first. Default says what it falls back to: the site's choice, or the agent's own size. The dialog's single Save keeps working as it does today. The buttons below are clickable, to try the help line.

5. Where the two rows differ, and why (your call)

  1. Codex has fewer steps (100k / 150k / 200k against Claude's 200k to 1M). Today's Codex models hold about 272,000 tokens and already tidy up at about 245,000, so bigger Codex steps would do nothing or run out of room. The effort strips already differ per agent in the same way.
  2. Only the Claude line mentions a command. Claude Code lets you change the size mid-session with /autocompact. Codex has no such command, so its line says when a change takes effect instead.
  3. Both new rows name their agent ("Claude memory limit"). The existing Claude rows above don't ("Starting model"). The separate tidy-up card for these settings (fae2ce4f) is the place to fix the old rows.
  4. Codex gets a Default button here, although its model row has none today. Both new rows work the same way.
  5. The terminal's "Starts on Opus · High" line doesn't mention the limit. I recommend leaving it out, because that line is already full.
