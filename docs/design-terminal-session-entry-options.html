Terminal session entry — three options

Rework of card cbe60db5 · reconnect / new / resume — Nick chooses the direction; nothing below is decided.

REWORK — v1 rejected 3 options, equal depth Dock · My sessions · Pop-out WCAG 2.1 AA · no hover-only · never colour alone
Why v1 was rejected — and what every option below fixes

1 · It designed for a dock that was already open. In reality the dock loads collapsed, and expanding it silently mints a brand-new session (the paired auto-connect on expand). The v1 "Reconnect" state was unreachable; every refresh-and-reopen spawned a duplicate — Nick ended up with three.

2 · It auto-decided. Nick, verbatim: "I should be able to decide myself whether I want an existing one, a new one or a resumed one."

Fixed in all three options: whenever you have any live or recent session, opening the terminal — via the dock chevron, the toolbar button, or a task launch — never silently creates and never silently reconnects. It always lands on a choice with three first-class answers: Reconnect · New session · Resume. The only automatic behaviour anywhere is the optional "instant continue" refresh variant in §2, clearly marked as Nick's to veto.

2 · Common foundations (shared by all three options)

F1 · The silent auto-mint dies. Today, expanding the dock auto-connects a paired browser (autoConnectWhenExpanded on the pristine slot). That behaviour survives only in the true empty state: no live sessions anywhere and no recent ended sessions → opening the dock launches a new session exactly as today (there is nothing to choose between, and this is explicitly fine). The moment the registry lists any live session or any resumable recent session for this user, every entry point routes to the option's choice surface instead. On board load the dock fetches the registry once (it already fetches for the My sessions badge) to know which world it's in.

F2 · Reconnect mechanics. Reattaching mints a fresh browser token for an owned live session id: no new registry row, exempt from the session cap and the mint rate limit (recovering capacity, not consuming it), but fully authenticated and ownership-checked. Scrollback: while attached, the dock snapshots the buffer to this tab's sessionStorage (pagehide + 20 s dirty-flag cadence); on reattach a snapshot restores with the divider — reconnected · earlier output restored —; with no snapshot, a dismissible amber note is pinned above the terminal — never a silently blank screen.

F3 · Take-over is always stated, never sniffed. We don't trust ourselves to know reliably whether another window currently holds the session, so every Reconnect control carries the same generic warning visibly, before the click — the click on Reconnect is the informed confirmation; no second click, no conditional logic: "If this session is open in another window or browser, connecting here takes over — that view stops receiving output."

F4 · Resume mechanics. Resume runs claude --continue in the session's recorded project folder, as a new session through the normal capped launch path (the confirm says so). Recent = ended in the last 48 h, max 5, one per project folder. Resume is hidden entirely when the project folder wasn't recorded — no disabled ghost button. The machine line uses the cautious copy by default: "The conversation lives on the machine that ran it — resume from a browser on that machine.", appending "(recorded as Nick's MacBook)" only when a label exists.

F5 · Popped-out window reload (same in all options). The popped window stashes its session id in its own sessionStorage at hand-off. On reload it shows a one-button Reconnect panel (with the F3 warning) — it never auto-attaches unless the instant-continue variant below is approved, in which case its own <60 s snapshot counts as proof. If the mint says the session is gone: "This session has ended. You can close this window — start a new one from the board." + a Close-window button.

Optional variant — "instant continue" on accidental same-tab refresh (Nick's to veto).
Justification: sessionStorage is per-tab and survives reload; a snapshot for this session id time-stamped under 60 seconds ago proves this exact tab held the session moments before. Only in that case, the dock may skip the choice and reattach automatically (restoring scrollback, zero clicks) — the refresher never even notices the reload. Every other case — new tab, restored browser, second machine, stale snapshot — always gets the explicit choice. This is off by default in this document; it ships only if Nick approves it, and it is the only automatic connect anywhere in any option.

Accessibility, all options: every state carries text (never colour alone — dots always sit next to words); all actions are visible buttons (no hover-reveals); choice surfaces are keyboard-traversable lists (Tab/↑↓, Enter activates); focus lands on the first live session's primary action when the surface opens; counts in headers are real text, not badge-only.

  • Collapsed bar gains the three count pills; chevron copy "Open/Collapse".

Pros

  • Explicit primary action for the newcomer path ("Start new session") — no ambiguity about what the big button does.
  • Task dedupe becomes visible and user-controlled rather than automatic.
  • One consistent surface regardless of entry point (chevron, toolbar, task).

Cons

  • Two clicks to a terminal every time sessions exist (unless the variant is approved).
  • Overlaps the My sessions panel — two surfaces listing sessions must stay consistent (mitigation: both read the same list endpoint).
  • A new full-body dock view to build and test; the heaviest new UI of the three (though not the heaviest overall — see C).

4 · Option B — "My sessions is the front door"

OPTION B

The collapsed dock header becomes informative and is the entry point: clicking it opens the existing My sessions panel, upgraded with Reconnect, Resume, and New session. The terminal area only opens once a session is chosen or created.

Flow walkthrough

Click the dock header"2 sessions running · 2 recent" — or toolbar / task launch→ My sessions panel opensNew session on top · Reconnect on live rows · Resume on recent rows→ One click in the panel→ Panel closes · dock expandsother-board rows navigate first→ Terminal live

The separate "My sessions" button disappears — the whole header is the trigger, so there is exactly one front door. Task launches open the panel with a context line ("Launching for task: fix-login-bug") and the New session button pre-scoped to that task; a live session for the same task shows Reconnect as its row's first action with the dedupe badge.

Required cases

What changes vs today

  • My sessions panel gains: New session button, Reconnect on live rows, a Recent section with Resume, this-board badges, one shared take-over caption.

  • The terminal opens behind a popover — an indirect, slightly admin-flavoured moment for the most common action.
  • Clicking a bar to get a popover (not an expansion) bends the dock's expand/collapse convention.
  • A popover is a cramped home for the task-launch context.

5 · Option C — "Tabs-first"

OPTION C

Opening the dock shows the tab strip immediately — one tab per live session in a resting "Reconnect" state, a "+" tab for new, and a slim Recent row beneath for Resume. Nothing connects until a tab's Reconnect is clicked. Closest to the current multi-tab mental model.

Flow walkthrough

Open dockchevron / toolbar / task launch→ Strip renders resting tabsone per live session on this board · ring-dot + "reconnect" text · first tab pre-selected→ Selected tab's body shows its Reconnect panelidentity, age, folder, take-over warning→ Click Reconnect (or "+", or Resume in the Recent row)→ That tab goes liveothers stay resting until clicked

Task launches focus the matching resting tab if that task already has a live session (dedupe made visible — it does not connect), otherwise they open a fresh tab whose body shows a "Start session for this task" panel with a single Start button.

The collapsed header shows the existing chip summary with a new chip: ◌ 2 to reconnect. The Recent row hides itself when empty; Resume opens the shared inline confirm (F4) as a small popover anchored to the button.

Required cases

  • Collapsed header: today's chip summary plus the resting chip — e.g. ◌ 2 to reconnect · ● 1 connected; "Terminals" wording unchanged.
  • Toolbar "Launch Claude Code → In the browser": opens the dock on the strip; task with a live session → focuses its resting tab; otherwise a new tab with a "Start session for this task — fix-login-bug" panel and one Start button. No sessions anywhere: launches immediately, as today.
  • Popped-out window reload: foundations F5 — unchanged by this option.
  • Accidental same-tab refresh: the tab this browser tab held is pre-selected in its resting state — reconnect is one click after opening. Instant-continue variant (if approved): that tab auto-connects on open (<60 s proof); the others stay resting.
  • Empty state: unchanged — no strip, no Recent row, today's single-session launch/setup panel.
  • Other-board live sessions: not in the strip (tabs stay board-scoped). The My sessions button remains the path — its live rows gain Reconnect in this option too, or those sessions would be reachable only by walking to their boards.

What changes vs today

  • New "resting/reconnect" tab state in the strip machine (glyph, aria text, body panel); tabs seeded from the registry on load instead of only from launches.
  • The strip now renders for a single resting session too — today's "no strip until 2+ tabs" rule gets an exception, or a sole session shows the C1 body panel without a strip (recommended: the exception; consistency beats minimalism here).
  • New Recent row chrome under the strip; autoConnectWhenExpanded gated as in F1; My sessions rows gain Reconnect for cross-board reach.

Pros

  • Zero new mental model — the tabs Nick already uses, with one new resting state.
  • Reconnect is two clicks with the right tab usually pre-selected; multiple reconnects are naturally per-tab.
  • After connecting, you're already in the exact UI you'll keep using — no surface hand-off.

Cons

  • Board-scoped: other boards' sessions are invisible in the strip — the three-way choice is only complete for this board; cross-board still detours through My sessions.
  • A slim Recent row is the least discoverable Resume home of the three.
  • Resting tabs risk reading as "connected" at a glance (mitigated by ring-dot + the literal word, but the risk is real).
  • Heaviest implementation: strip state machine, single-tab strip exception, Recent row, per-tab reconnect panels, plus the My sessions Reconnect upgrade anyway.

6 · Shared edge cases (all options)

Edge caseBehaviour
Reload during the helper's 60 s post-exit linger The registry may still list a session whose Claude process has already exited. The choice surface honestly shows it live; clicking Reconnect mints fine but the attach lands on a dying/dead leg → the standard failure path shows "Couldn't reconnect — the session may have just ended." with Retry, the list refreshes, and the session reappears under Recent (with Resume, if its folder was recorded). No special pre-detection — the copy absorbs the race.
Session ends between listing and click The reattach mint returns "gone" → same inline error and list refresh as above. The row/tab is replaced, never left as a dead button. In the popped window this becomes the F5 end-state ("This session has ended…").
Two browser tabs both showing the choice surface Both legitimately list the same live session — that's why the take-over warning is unconditional (F3). Whoever clicks first attaches; the second click also succeeds and takes over (the first view gets the existing duplicate-preemption close and shows its normal "connection replaced" state, with its own Reconnect path back). Lists refresh on window focus so counts don't go stale between the two tabs.
Cap reached while choosing Only "Start new session" / "+" / Resume are capped (F2/F4) — they fail with the existing cap toast that opens My sessions. Reconnect always works: it is exempt by design.
