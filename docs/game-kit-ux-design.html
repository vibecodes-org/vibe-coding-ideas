Headline decisions
  1. OQ1: the kit's stored name is Game, not "Create a game". The "create a game" wording goes in the card description. Reason and side-by-side in §4.
  2. No new components. The picker and preview are data-driven; the whole feature is one data migration plus two small edits to the preview (§6).
  3. One snag Requirements didn't catch: a label can only trigger one workflow (database rule: one row per kit + label). The 9-label list has "Milestone/Spike" driving two workflows. Recommend splitting it into Milestone and Spike — 10 labels. Detail in §3.

3.1 Labels and which workflow each one triggers

Constraint the Implementation step must respect: the trigger table has a uniqueness rule of one row per (kit, label). A label can start one workflow only. Requirements listed "Milestone/Spike" as one label but "Milestone Gate" and "Technical Spike" as two workflows — one of them would be unreachable (and because the preview derives its workflow list from the trigger rows, the orphan wouldn't even appear in the panel). Recommendation: split into two labels, Milestone and Spike. That makes 10 labels, not 9. Alternative if the human prefers to stay at 9: drop the Technical Spike workflow into the Milestone Gate one as an optional step. I prefer the split — a spike and a milestone review are different jobs with different owners.

The "Create a game" phrasing the brief asked for survives — it is the first two words of the description, which is the first thing the eye reads after the icon.

5. Accessibility

  • Contrast. Card name #fafafa on zinc-900 ≈ 17:1. Description (zinc-400 on zinc-900) ≈ 7:1. Label pills: 400-shade text on a 12% tint over zinc-900 — lowest pair is amber-400 ≈ 9:1, cyan-400 ≈ 10:1. The dimmed "recede" state (60% opacity) brings zinc-400 to ≈ 4.6:1 — still passes AA for the small description text and restores to full on hover/focus. The tiny section headings (8.8px, 70% zinc-400) are ≈ 4.7:1 — they pass, but only just; they are existing and unchanged.
  • Keyboard. The grid is a radiogroup; arrow keys move and select, Tab enters/leaves. Adding a sixth card changes nothing — the handler wraps around buttons.length. Workflow pills in the preview are real <button>s. No hover-only actions anywhere.
  • Not colour alone. Labels are identified by their text; colour is a secondary cue. Approval gates use 🔒 + an amber border + the key line, not amber alone. The primary workflow uses a violet dot + first position, not position alone.
  • Screen readers. Each team chip has the full role in title; the preview is aria-live="polite" so choosing a card announces its contents. Recommend the chips also get aria-label={role.role} so the abbreviation ("Levels") isn't the only thing read — a one-line optional improvement, not blocking.
  • 375px. Two-column grid, three rows, no horizontal scroll. Team row wraps (after the §6 fix). Six workflow steps wrap to two lines. Card touch targets ~160×84px.
  • Motion. Panel slide-in is 200ms and the existing Tailwind animate-in honours prefers-reduced-motion via the app's global setup — no new animation added.
