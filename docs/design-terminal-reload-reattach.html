2 · Decisions in full

D1Board reload: hybrid auto / one-click

On board load the dock queries the registry for live sessions on this idea (it already fetches for the My sessions badge). Each live session gets a dock tab in a "Reconnect available" state. Then:

  • Auto path — if sessionStorage holds a snapshot key for that sid whose timestamp is < 60 s old, this exact tab held the session moments ago (sessionStorage is per-tab and survives reload). The dock reattaches automatically: mint → attachExisting → restore snapshot. Zero clicks; the refresher never even sees the Reconnect state.
  • One-click path — no fresh proof (new tab, restored browser session, second browser): the tab shows a Reconnect panel (§4, mockup M1). One click reattaches. This satisfies the "at most one click" requirement while making take-over of a possibly-live view elsewhere a deliberate act.

Why the 60 s guard: some browsers restore sessionStorage across a full browser restart. A tab restored hours later auto-grabbing the session would silently kick a view that moved to another machine in the meantime. Fresh timestamp = safe; stale = ask.

Rejected — unconditional auto-reattach: attaching is same-owner take-over; a second browser opening the board would automatically kick the first browser's live terminal with no warning. Automatic preemption is a surprise-machine. Rejected — always one-click: punishes the accidental-reload story (the most common case) with a needless click and a flash of "disconnected" UI when we have proof it's the same tab.
D2Pre-reload scrollback: sessionStorage snapshot + honest fallback

While attached, the dock snapshots the serialized buffer (existing scrollback module, already capped at 1 MiB) into sessionStorage:

  • When: on pagehide (the reload moment) and every 20 s, but only if output arrived since the last write (dirty flag) — no idle churn.
  • Key scheme: vc:term:snap:<sid> → { v:1, ts, data }. Versioned so a format change can be dropped cleanly.
  • Eviction: deleted when the session ends cleanly, when the tab is closed via ×, and on successful restore-then-supersede (each new write replaces the old). On QuotaExceededError: delete all other vc:term:snap:* keys, retry once, otherwise skip silently — the honest note covers it.
  • Restore: reattach passes the snapshot as initialBuffer through the existing attachExisting path, then renders the divider "— reconnected · earlier output restored —".
  • Honest fallback: no snapshot (tab-closer, second browser, quota skip, stale version) → dismissible amber note pinned above the terminal (mockup M3): "History from before you reconnected isn't shown here — it's still in Claude's context. New output appears below." Never silently blank.

Truth split, stated plainly: sessionStorage survives reload in the same tab only. The refresher gets history back; the tab-closer and second-browser cases get the honest note. The note never claims history is lost — Claude's own context is intact on the machine.

Rejected — no snapshot, note only: the refresher story explicitly asks for continuity; a blank terminal after a 2-second accident feels like data loss even with a note. Rejected — server-side scrollback store: real continuity everywhere, but new storage, retention, and privacy surface for terminal output — out of proportion for this card (listed in out-of-scope).
D3Reconnect in My sessions (live rows)

Every live row gains a sky Reconnect button placed left of the rose End button (primary-action-first, destructive-last — matches the row's existing layout grammar). Behaviour:

  • Same idea's board: activates/creates the dock tab and reattaches in place. Panel closes.
  • Different idea: navigates to that idea's board with ?reconnect=<sid>; the dock reads it, reattaches, and cleans the URL. A sid is an identifier, not a credential — the mint still requires auth + ownership, so no token ever appears in a URL.
  • States: default → Connecting… (spinner + word, not spinner alone) → success closes panel / failure shows inline row error "Couldn't reconnect — the session may have just ended." with Retry.
  • Attached elsewhere: if the registry marks the session as currently attached, the button first swaps the row into an inline amber confirm (same inline-confirm pattern as End all): "This session is open somewhere else (Nick's MacBook · Chrome). Reconnecting here takes it over — the other view stops receiving output." → Cancel / Take over.
Rejected — whole-row click to reconnect: an invisible affordance next to a destructive End button invites misclicks and fails recognition-over-recall; explicit labelled buttons are the panel's established pattern.
D4Resume for ended sessions (Half B — minimal but real)

My sessions gains a second section, "Recent", under the live list: the user's most recently ended sessions (last 48 h, max 5, newest first, one per project directory). Each row shows the same identity line (task/idea, machine label, age → "ended 2h ago") and an emerald Resume button. Clicking swaps the row into an inline confirm (mockup M2, third row) that tells the whole truth before anything launches:

  • It starts a new session and counts toward the session limit.
  • It continues the most recent conversation in that project folder (exact-conversation pick is deferred — the copy says "most recent", never "this exact one").
  • Machine truth: the conversation lives on the machine that ran it. Confirm line: "Runs on Nick's MacBook — resume from a browser on that machine." If the label is unknown: "We can't tell which machine ran this — resume only works on the machine that holds the conversation." We cannot detect which machine the current browser sits on, so we state the requirement rather than pretend to verify it; if the wrong machine launches, the standard launch-failure state appears and the user has been fore-warned.

Confirming fires the existing vibecodes:// launch flow with the recorded project directory and a claude --continue variant of the launch command. The helper's quit-when-idle is a non-event: the protocol link wakes it exactly as a fresh launch does, and the new dock tab shows the existing launch-phase progress ("Starting the helper… · Launching Claude…").

Rejected — Resume button on the board / ended dock tab: ended sessions vanish from the dock by design; resurrecting ghost tabs to host a button reintroduces clutter the linger design removed. My sessions is already the "everything of mine, across ideas" surface — one home, findable (Jakob: matches "recent items" sections users know from editors and terminals).
D5Popped-window reload: reattach in place

Today a popped window's reload dead-ends on "Lost the session hand-off" (stale nonce, no opener). Fix: at hand-off time the popped window stashes vc:pop:sid (+ idea id, for labels) into its own sessionStorage — same-tab, so it survives reload. On load, if the nonce hand-off fails but the stash exists: reattach mint → attachExisting → same session in the same window, with its own D2 snapshots giving it the same scrollback behaviour as the dock. If the mint says the session is gone, an end-state replaces the error: "This session has ended. You can close this window — start a new one from the board." + a "Close window" button.

Rejected — window.name carrying the sid: window.name persists across cross-origin navigation (leaky) and already carries the nonce; overloading it is fragile. Rejected — "return to the board" message: fails the stated requirement that a pop-out reload reattaches, and punishes an accidental ⌘R in the very window the user deliberately isolated.
D6Cap / rate exemption (requirement for Implementation)

The reattach mint is a new mode on the existing session API: given an owned, live sid it returns a fresh browser token, creates no registry row, and bypasses both the session cap and the rate limit — reattaching is recovering existing capacity, not consuming new capacity. It remains fully authenticated and ownership-checked against the registry (owner-only, per requirements). Resume (D4) is deliberately not exempt: it is a genuine new launch and goes through the normal capped path — the confirm copy says so.

Rejected — counting reattach against the rate limit: a flaky network or impatient double-reload would lock a user out of their own still-running session — the exact failure the refresher story forbids.

6 · Edge cases

CaseBehaviour
Reload during linger (session ending, helper counting down to quit)Registry still says live → reattach succeeds and the user sees the normal linger/ended progression. If it flipped to ended mid-mint, the mint fails → Flow 1C ended state. No special UI.
Session expired between snapshot and reattachMint returns "gone" → ended state; the stale snapshot for that sid is deleted. Never render a dead snapshot as if live.
Two tabs, same sidAttach is same-owner take-over: last attach wins; the earlier tab drops to the Reconnect panel (M1) rather than a broken stream. The auto path can't ping-pong — only a tab with a <60 s snapshot auto-attaches, and losing the attachment stops its snapshots.
Snapshot write exceeds quotaEvict other vc:term:snap:* keys, retry once, else skip. Reattach then shows the honest note — degraded, never wrong.
Resume clicked while helper is mid-quitvibecodes:// relaunches the helper (existing path). Worst case the launch-phase UI sits on "Starting the helper…" a few seconds longer. Timeout uses the existing launch-failure state.
Resume on a machine without the conversationFore-warned in the confirm; Claude simply starts fresh (--continue with nothing to continue) or the launch fails on a machine without the helper — both are existing states.
?reconnect=sid for a session that isn't yours / doesn't existMint is auth + ownership checked → param ignored, URL cleaned, no error surfaced (nothing the user did wrong on this page).

Accessibility notes

  • All new actions are visible buttons — nothing hover-revealed; every state has a text label alongside its colour/icon (dots never stand alone; the panel headline restates the state).
  • Reattach state changes announce via the dock's existing aria-live region ("Reconnected to fix-login-bug", "Session ended").
  • Inline confirms (take-over, resume) move focus to the confirm's first button and restore it on cancel; Esc cancels.
  • The history note is role="status", dismiss is a real button with aria-label.

Out of scope (this card)

  • Server-side scrollback persistence (cross-tab / cross-machine history restore).
  • Exact conversation-id capture and a conversation picker — Resume is most-recent-in-directory only (deferred per requirements).
  • Detecting which machine the current browser is on (would need helper-side pairing signals).
  • Realtime registry push to the dock (fetch-on-load / on-open stays, per the My sessions brief).
  • Resuming into a different project directory, or resume for sessions older than the registry window.
