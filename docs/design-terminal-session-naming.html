Terminal session names that stick

UX design for card 3bf262ac — rename on tab, My Sessions and chooser rows; one naming rule everywhere. Builds directly on the Requirements step (ProdOwner, 2026-08-20): its precedence rule, its ended-session PATCH finding and its acceptance criteria are taken as given and referenced by number below, not restated.

Step 2 — UX Design 3 surfaces × 3 states, wireframed WCAG 2.1 AA · no hover-only affordances · never colour alone Never tear down a live xterm · never a trapping dialog

The two decisions this document makes

  • Fallback shape (the open question Requirements §3 left to design): full idea title, not the slug. Vibe Coding Ideas · a3f9, never vibe-coding-ideas · a3f9. Rationale in §1.
  • Discoverability: a visible pencil control on the active tab and on every row, with double-click and F2 as desktop accelerators. Rationale and rejected options in §2.

1 · The naming rule, made visible

Requirements §3 fixes the precedence; every surface calls one helper:

1 · Your nameuser-set, trimmed, if non-empty→ 2 · Task titlecaptured at launch from the card→ 3 · Fallbackidea title · first 4 of session id

Decision: the fallback shows the full idea title, not the slug

Chosen: Vibe Coding Ideas · a3f9. Rejected: vibe-coding-ideas · a3f9 (today's tab label). Why:

  • The slug is an internal artifact leaking into UI. It exists to build folder paths for launch commands. Lowercased-and-hyphenated text reads as a machine identifier, and it sits directly above a monospace ~/projects/… line in every row — two path-looking strings stacked is exactly the "which one is the name?" confusion this card is fixing.
  • Names are read, not typed. Nobody ever enters this label anywhere; the only job it has is recognition (recognition over recall). The title as the user wrote it — capitals, spaces — is the version they recognise.
  • It changes the fewest shipped strings. The chooser already shows the full idea title in its fallback (Requirements §2, label drift). Unifying on the title means the chooser's rows barely change while the tab and My Sessions get more readable; unifying on the slug would make every chooser row worse to fix a drift.
  • The 4-char id suffix stays — it is what tells two toolbar sessions on the same board apart, and today's chooser fallback (idea title alone) lacks it. Same length everywhere: 4, never 8 (the chooser's current 8-char last resort goes).

Edge: if the idea title itself is missing/blank, the fallback is Session · a3f9 — never a bare id, never an empty left half.

De-duplication rule for rows: chooser and My Sessions rows show the idea title as a secondary chip after the name. When the resolved name is the fallback (so it already contains the idea title), the secondary chip is suppressed — otherwise every toolbar session reads "Vibe Coding Ideas · a3f9  Vibe Coding Ideas".

2 · Discoverability — how anyone finds out renaming exists

The constraint set: hover-only affordances are banned (mobile has no hover), a dock tab is a small, crowded target (status glyph + label + close in ≤190px), and per the shipped invariants no rename affordance may be a dialog that traps or a body-swap that tears down the terminal. Three candidate affordances, considered honestly:

AffordanceDiscoverable?Mobile?Verdict
Double-click the label Invisible — a convention (iTerm2, VS Code workspaces, file managers) that power users try and nobody else finds No — double-tap is unreliable and conflicts with tap-to-activate Keep as an accelerator only, never the sole path
Context / kebab menu per tab A kebab is findable, but the dock has no per-tab menu today — inventing one to hold a single item is a heavier pattern than the feature needs (Hick's law: a menu of one is a button wearing a costume) Long-press menus are undiscoverable Rejected — revisit only when tabs accrue 3+ actions
Explicit pencil control Visible = discoverable. On rows there is room for it always; on tabs it renders on the active tab only Yes — a 24px+ visible tap target (44px hit area via padding) Recommended — the primary affordance everywhere

Recommendation: pencil everywhere, gated by activation — never by hover.

  • Rows (My Sessions, chooser): a pencil icon button rendered on every row, always, between the text block and the action buttons. Rows have the horizontal room; no gating at all.
  • Tabs: the pencil renders on the active tab only, next to the close button. A background tab is one tap/click from being active — the same interaction the user already performs to do anything with that session — so the affordance is activation-gated, which is allowed, not hover-gated, which is banned. This keeps background tabs at two elements (glyph + label + close) instead of four, and puts the control exactly where the cursor already is when the user is looking at the session they want to rename (Fitts).
  • Accelerators (additive, desktop only): double-click on the active tab's label, and F2 while a tab has keyboard focus (the file-manager rename convention). Both open the same inline editor as the pencil. The pencil's tooltip teaches them: "Rename session (double-click or F2)".
Why the tab pencil is not on every tab: with the close button already permanent, a second permanent icon on every background tab shrinks the label — the thing this whole card exists to make legible — below usefulness at the 110px minimum tab width. The active-only rule trades one extra click on background tabs for label space on all of them.

4 · Edit-mode specification

AspectSpec
EntryPencil click/tap · double-click on the active tab's label · F2 with a tab focused. All three open the same editor in place; nothing else about the surface changes; the terminal body is never swapped or unmounted.
PrefillThe user-set name if one exists, fully selected (one keystroke replaces, arrow keys edit — the file-rename convention). If no user name is set, the field is empty with the current auto-name as placeholder. Never prefill the task title as if it were user text — that would make "clear back to auto" require knowing what to delete.
Input stylingSame footprint as the label it replaces; bg-zinc-900-family field, 1px sky border + soft sky ring (the app's focus treatment); text at the surface's label size; dir="auto".
Character limit100 (server-enforced per Requirements §4, trimmed). maxLength=100 on the input so the wall is physical, plus a live 87/100 counter that appears from 80 characters — the limit is communicated before it is hit, never only by keystrokes silently dying. Counter is aria-live="polite"-adjacent via aria-describedby. Length counts Unicode code points, matching the server rule, so emoji don't desync client and server.
SaveEnter, the ✓ button, or blur (clicking elsewhere saves — the Notion/Linear convention; losing typed work on blur is the worse failure). Trimmed before compare; a no-change save is a silent close, no network call.
CancelEscape or the ✕ button — discards, restores the previous label, no network call. Escape in the chooser cancels the edit only; the chooser itself stays dismissable as shipped.
ClearSave with an empty/whitespace field → the name is cleared (stored as NULL, never "") and the auto-name returns instantly. The placeholder showed exactly what would come back, so this is never a surprise.
Optimistic updateOn save: the resolved name updates immediately on the initiating surface and in the dock's local session entry (so the tab, pop-out title and aria announcements agree), then the PATCH fires. Other surfaces pick it up on their next fetch-on-open (§5, flow F7).
FailurePATCH fails / offline: revert the optimistic name everywhere it was applied, then toast.error naming the session it still is (see mock) with a Retry action that re-submits the same attempted name — the user's typed text is held in state and never lost. No client catch block fails silently (project rule).
Busy stateNone visible in the happy path — optimistic means no spinner on the label. The editor closes on save immediately.
Concurrent editsLast write wins server-side; no locking. Two-tab staleness handled in flow F7.

F5 — Rename while the session is reconnecting

A rename is a database write about the session, not traffic on the session — it needs no live socket. The editor opens and saves normally while the tab shows the ↻ reconnecting glyph; the glyph stays visible beside the editor throughout (status is never hidden by an edit). If the session dies mid-edit, the save still succeeds — it's now simply a rename of an ended session (F2's path).

Accepted staleness: the registry is already fetch-on-open everywhere (My Sessions, chooser); the design adds no realtime requirement. What the design does require: a surface must re-resolve names from fresh data every time it opens — never cache a resolved label across opens.

6 · Accessibility

  • Labels. Row editors get a visible "Name" text label (mock 3b) — there is room, so it exists. The tab editor cannot fit a visible label in ≤230px; its accessible name is aria-label="Session name" and its context is carried by the launching control's own name ("Rename session: Fix login redirect loop"). The placeholder shows the auto-name but is never the only label anywhere.
  • Keyboard-only path, end to end. Arrow keys move through the tab strip (shipped roving tabindex) → F2 opens the editor → type → Enter saves / Escape cancels. On rows: Tab reaches the pencil (it's a real button in the tab order) → Enter opens → same keys. The ✓/✕ buttons are focusable for users who prefer buttons over keys.
  • Focus management. Entering edit: focus moves into the input, existing text selected. Leaving edit (save or cancel): focus returns to the control that opened it — the pencil (or the tab itself for F2/double-click entry). Focus never jumps to the terminal, and never falls to body.
  • Announcements via the dock's existing polite announcer: entering edit says nothing (the focused input announces itself); on save, "Session renamed to auth spike"; on clear, "Name removed — using automatic name Vibe Coding Ideas · a3f9"; on failure, the toast is the announcement (sonner is live-region-backed). Background-tab attention announcements (formatAttentionAnnouncement) automatically use the resolved name since they take the label as input.
  • The PTY must never eat — or be fed by — rename keystrokes. While the editor is open, all keydown/keypress events stop at the input (stopPropagation): the tab strip's arrow-key navigation is suspended for keys the input consumes, xterm.js must not steal focus back (its click-to-focus only fires on terminal clicks, but guard the dock's own focus-restoring effects), and the Enter that saves must never leak a newline into the shell. Conversely typing in the terminal must never trigger F2/double-click handlers — those bind to the tab strip, not the dock.
  • Contrast & non-colour signalling. Editor border sky-on-dark ≥3:1 (UI component minimum); counter amber ≥4.5:1 at its size; the just-saved emerald flash is decorative only — the durable signal is the changed text plus the announcement, never the colour. Status glyphs remain shape-distinct per terminal-tabs.ts.
  • Touch targets. Pencil buttons render ≥24px with padding extending the hit area to 44px; the tab pencil's hit area may share the tab's vertical extent (38px) — acceptable as an inline exception, with the row surfaces as the full-size path to the same action.

7 · What the engineer must not break

  1. Never tear down a live terminal to rename it. The editor is an in-place contents swap (like the tab's End-session confirm) — never a dock-body swap, never an unmount of TerminalSessionView, never an overlay over a live tab.
  2. Never a trapping dialog. There is no rename dialog at all; the inline editors always exit via Escape/✕/blur. The chooser stays closable during and after an edit.
  3. Ended rows must accept the name PATCH — display_name only. The bridge-fed fields (cwd, machineLabel, claudeSessionId) keep their active-only, set-never-clear semantics untouched.
  4. Renaming never affects matching or dedupe. Task-session matching and tab dedupe key on taskId/sid, never on the label (AC 10).
  5. Clear stores NULL, never an empty string; whitespace-only input is a clear.
  6. A popped-out tab's status must not be misread during rename — the ⧉ display status and its "deliberate user state, never attention" rule stand; renaming a popped-out session is allowed and updates the pop-out window title.
  7. Sessions with no recorded folder stay hidden from the chooser but remain in the internal reconnect check — the rename UI adds no new visibility for them.
  8. The name rides resume. buildResumePayload and the mint body carry displayName exactly as they carry taskId/taskTitle — skip this and the core ask ("names that stick") silently fails on the most common path.
  9. One helper, all surfaces. Tab, chooser (live + recent), My Sessions, pop-out title, aria announcements, and the future side-by-side pane headers (card df7a0134) all call the same resolveSessionName — no surface re-derives its own label ever again. The sid suffix is 4 chars everywhere; the chooser's 8-char last resort goes.
  10. The sr-only status text and glyph vocabulary in terminal-tabs.ts are reused, not forked.
