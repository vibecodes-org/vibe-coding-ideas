One tier, two agents: what Frontier / Standard / Cheap mean when Codex runs the step

The Requirements step (FR-1…FR-8, AC-1…AC-15) settled the shape: tiers stay abstract, and each tier now resolves to a Claude model and a Codex model. Nick's review added one symmetry: both sides carry a reasoning effort, so an override on either agent is always a model plus an effort. This document implements FR-7 (UI surfaces) and supports AC-3, AC-4, AC-11 and AC-12.

The design has one recurring element: a resolution line. Wherever a tier appears, the same short line says what it becomes on each agent — Frontier → Opus (high) on Claude · gpt-5.2 (high) on Codex. It sits under each tier row in settings, in the tier picker's helper text, and in the completed-step record. Learn it once, read it everywhere.

Refines FR-7

An override on either agent is one value (model + effort), never two independent fields. You can't set an effort without picking a model, and picking a model makes effort required. This is what makes AC-3's error possible to explain in one sentence — and it now applies to Claude exactly as it does to Codex.

Refines FR-7

The Profile dialog widens (Nick approved) rather than gaining Claude/Codex tabs. Tabs would hide one agent's values while you edit the other; a reviewer needs both on one screen to see that a tier means the same thing on both. Both agent cells share one shape, so the grid reads as a clean table.

Unchanged from today

Save is the only write. Reset stages locally. Cancel/Esc discards. "Platform default" remains the unset state per agent. Existing Claude-only users see their model values exactly as before, with effort and the Codex column reading "Platform default" (AC-2).

Tier labels render immediately; the controls stay disabled with placeholder bars until the platform defaults arrive (usually under a second). The dialog never opens on an empty body.

  • One cell shape for both agents (rev 2). Every agent cell is a vertical pair — model select over an Effort segmented control — with fixed row heights (36 / 14 / 36 px). Because the grid's two agent columns are equal width and each cell is top-aligned with identical internals, selects align with selects and effort controls with effort controls across Frontier, Standard and Cheap. Nothing sits beside the select any more, so nothing can overflow the dialog edge; the segmented control stretches to the column width. An inline error or warning adds a fourth line under its own cell without shifting the controls in neighbouring cells.
  • Effort is a segmented control, not a select. Three fixed values, all visible, one tap each — no menu to open (Hick's Law, recognition over recall). It only becomes live when a model is chosen; while the model is "Platform default" it shows the default's effort pressed but greyed, so the reader still sees what will run.
  • Claude effort = thinking level. For Claude the Low / Medium / High segment maps to the extended-thinking / reasoning level; the exact values behind each label are pending the same quick check as the Codex effort ladder, and the column header says so in a small caption. Only the labels are fixed by this design.
  • The pair is atomic on either agent (refines FR-7). Choosing a model clears the effort to "unset" rather than silently inheriting the default — the person must confirm the effort, which is the whole point of FR-6. Switching back to Platform default clears both and removes any error. The AC-3 error is drawn on the Codex side above; the Claude side uses the identical rose treatment and sentence ("Choose a reasoning effort for Fable.").
  • AC-3 error is inline, adjacent, iconed and worded. Rose border + triangle icon + a sentence that names the model and says exactly what to do. The Save button's hint names the tier and agent that is blocking. Never colour alone.
  • "Custom…" on the Codex model mirrors the existing terminal starting-model escape hatch: a free-text input with the same shell-safety validation (FR-1) and the same amber "not a known family" advisory. Effort is still required for a custom id.
  • Mid-run tier change. The tier help says "Live sessions pick this up on their next step" — a step already running finishes on the model and effort it started with; the next claim resolves against the new mapping.
  • Terminal starting model is unchanged for Claude and gains one help sentence stating how Codex launches pick their model. The Codex starting-model picker is a separate, deferred task on the board, not part of this feature's first release — the copy says so, so nobody reads the gap as an omission.
  • Width. The dialog moves from sm:max-w-md to sm:max-w-2xl (Nick approved). At that width the grid is 120 px + two equal 264 px agent columns with 14 px gutters — the longest default label ("gpt-5.1-mini · low (default)") and the three-button segment both fit with room to spare. Below 640 px the grid stacks (tier, then "Claude" pair, then "Codex" pair with the agent name as a small caption above each).

  • Format is fixed: <Tier> → <Claude model> (<effort>) on Claude · <codex model> (<effort>) on Codex. Claude models keep their capitalised alias (Opus); Codex ids stay lowercase as typed, because that is what a person will see in their terminal. Effort is always lowercase in brackets on both sides.
  • Viewer-resolved, as today. The helper follows the viewer's own mapping first, then the live platform default, then seed — the existing Design-Review condition 3 extends to Codex and to effort. A small "your mapping" badge appears when the viewer's override changed the line.

  • Effort always in brackets after the model, on both agents. A Claude record that predates effort (or a report that omits it) reads "Ran on Opus" with no brackets — never "(n/a)" — and is judged on model alone, so old records don't turn amber overnight.
  • The mismatch sentence names the part that differed. When only the effort was wrong, the expected effort is highlighted and the sentence says "same model, lower reasoning effort" — otherwise a reviewer sees two identical model names and can't tell why it's amber. This works identically for a Claude step that ran Opus (medium) against a Frontier (high) promise.
  • Agent chip on every line. Now that both agents carry effort, the chip is the one thing that tells a reader which ladder the effort belongs to, so it shows for Claude as well as Codex. It reuses the terminal's existing neutral chip. Pre-existing records with no agent recorded show no chip, exactly as today.
  • Status is never colour alone: tick / triangle / question-mark icons, distinct border styles (solid / solid / dashed), and the words "honored", "not honored", "not reported".

OQ-2
Per-step model resolution on Codex — yes. The tier picker keeps its promise that whichever agent claims a step runs it on that tier's model. No session-level softening of the "not honored" state is needed.

Effort is a separate field, on both agents — yes. Claude gains the same model + effort pair as Codex; the two columns are now the same shape, the resolution line carries effort on both sides, and AC-3's "model without effort" rule applies to either agent.

Terminal starting model for Codex — deferred to a separate task. Not part of this feature's first release. Until it lands, Codex launches start on the Standard tier's Codex model, and both the Profile help text and the terminal tooltip say so. The Claude starting-model control is unchanged.
OQ-6
Mid-run tier change — applies on the next step. A step already running finishes on what it started with. Help text on the Profile dialog, the admin card and the tier picker reads "Live sessions pick this up on their next step."
Design
Dialog width — widened, approved. sm:max-w-2xl. With the stacked pair in both agent columns (120 px + 264 px + 264 px at that width) every control fits inside the column and nothing overflows the dialog edge.
