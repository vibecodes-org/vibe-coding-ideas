2. Settings → Model Tiers dialog, "Terminal sessions" group

The workflow tier grid above this group is unchanged and left out to save space. The new row copies the auto mode row exactly: the same Switch, label on the left, help text underneath, id="terminal-remote-control", label linked with htmlFor, help linked with aria-describedby="terminal-remote-control-help". The switches here really work: click one or press Tab then Space, and you'll see the help text change and Save turn on.

Loading and errors are already handled by the dialog, so nothing new is needed. The tier grid shows grey placeholders while the platform defaults load; the terminal switches don't wait on that, which is how auto mode works today. If saving fails, the existing red pop-up says "Failed to save model tiers — try again" and the dialog stays open with your change still in it. If it works, the dialog closes with "Model tiers saved".

Fallback and sign-in variants (help text only, layout identical)

3. Launch chooser: the "Start new session" block

This is the block at the top of the session chooser, with the model line underneath. The new label goes on the same line, straight after "⚡ auto mode on" (or straight after the model line if auto mode is off). Each label keeps itself on one line (whitespace-nowrap), so on a phone the whole label wraps to the next line rather than breaking in the middle. The faded rows underneath are just there for context.

4. Per-task launch dialog ("This task has a recent session")

Same rule: the label sits on the "Starts on …" line straight after "⚡ auto mode on". If resumed sessions get Remote Control too (the expected result), Resume also starts with it on, so no extra reminder line is needed. If they don't, the fallback reminder in section 5 appears.

5. Only if resumed sessions can't get Remote Control

Shown only if the live check on resumed sessions fails. It's a separate line under auto mode's existing reminder, so the wording you've already approved isn't touched.

7. Keyboard, labels and contrast

Keyboard and screen readers

  • The switch is a real role="switch" (Radix). Tab reaches it straight after the auto mode switch; Space toggles it.
  • The visible label is linked with <Label htmlFor="terminal-remote-control">, so clicking the words toggles it and a screen reader reads "Start with Remote Control on, switch, off".
  • The help text is linked with aria-describedby, so the privacy sentence is read out when the switch gets focus.
  • Focus ring: the shared Switch's 3px ring (shown in state B below). It's unchanged and the same as auto mode's.
  • On and off aren't shown by colour alone: the thumb moves, and the help text changes its words, not just its colour.
  • The launch label is text with an emoji. Screen readers read "mobile phone, remote control on". If Nick wants that quieter, wrap the emoji in aria-hidden (auto mode's ⚡ isn't wrapped today, so leave it as it is to match).
  • The tap area on a phone: the whole label row is clickable (the label is linked), so the target is the full row width, well over 44px wide.

8. Session badge (the optional "Could" item): recommend not building it

No mock, on purpose. Claude Code already shows its own Remote Control notice inside the terminal, so a VibeCodes badge in the dock header would say the same thing twice. The header already carries the agent name, the auto mode badge and status. The badge would also mean extra work in the pop-out window and the reload code for little benefit. If you later find you can't tell which sessions have it on, it's a small follow-up: a violet "📱 Remote" badge beside the existing "Auto mode" badge, using the same wording constants.

9. What Nick decides at Technical Design

  1. Switch label: "Start with Remote Control on" (recommended) or "Continue sessions from your phone".
  2. Launch label wording and spot: "📱 remote control on" (recommended) or "📱 phone access on", placed straight after "⚡ auto mode on" on the same line, in the chooser and the per-task box. This adds to a screen you've already approved.
  3. Colour: violet for the launch label and the "on" help text (it pairs with auto mode's amber), or plain grey if you'd rather not bring a new colour onto the terminal screens.
  4. Session badge: agree to leave it out (recommended)?
  5. Separate small fix, not part of this card: the existing grey model line on the launch screens is slightly too faint to meet the accessibility bar. Do you want a follow-up card to brighten it (zinc-500 to zinc-400)?

No decision needed: if resumed sessions can't get Remote Control, or if a claude.ai sign-in turns out to be required, the fallback wording above is used automatically, as agreed in Requirements.
